# 운동 리포트 AI 확장 API 계약 — 검토 중

- 작성일: 2026-09-15
- 최종 수정일: 2026-09-15
- 버전: v0.3
- 상태: 검토 중

## 범위

완료한 본인 헬스 세션의 기본 리포트에 해석을 추가한다. 기존 `GET /api/v1/workout-sessions/{sessionId}/report`는 유지한다. 러닝 종합 AI 리포트, 질환 판단, 적정 중량 처방, 공개 서비스 정책 확정은 이번 구현에 포함하지 않는다.

서버가 계산한 기록을 근거로 AI가 목표·수행 변화·선택 체성분·기기 요약을 연결한 종합 평가, 관찰 2~3개, 다음 행동 1~2개를 작성한다. 각 문장은 근거 ID를 참조하며 화면의 근거 수치는 서버에서 붙인다. `methodVersion=grounded-narrative-v2`로 이전 후보 선택 방식과 구분한다. 기존 `grounded-selection-v1` 저장 결과는 그대로 조회한다.

생성 JSON의 길이·항목 수·중복 제목·허용 근거·필수 출처 포함을 검증한다. AI 본문에는 숫자를 쓰지 않고 수치는 서버 근거에 표시한다. 운동명은 지역 참조 토큰을 서버가 실제 이름으로 치환한다. 별도 AI 검토 호출에서 근거 모순·부적절한 단정·누락 정보 사용을 확인하며 실패·거절·시간 초과는 기본 리포트로 대체한다. AI 검토는 의미적 정확성을 완전히 보장하지 않으며 화면에 해석 오류 가능성을 알린다.

## API

공통 경로: `/api/v1/workout-sessions/{sessionId}/insights`. 인증이 필요하며 선택 정보·생성·조회·취소 모두 세션 소유권과 완료한 헬스 세션인지 검사한다.

| Method / 경로 | 동작 |
|---|---|
| GET `/options` | AI 사용 가능 여부, 별도 동의 버전·문구, `samsungHealthAvailable`(본인 세션에 저장된 요약 유무) |
| POST 공통 경로 | 비동기 분석 생성 |
| GET 공통 경로 | 가장 최근 요청 또는 null |
| GET `/{id}` | 요청 상태·저장 결과 |
| POST `/{id}/cancel` | 진행 중 요청의 결과 반영 취소 |

생성 입력: `requestId` UUID, 선택 `inbodyRecordId`, `includeSamsungHealth=false`, `externalAiConsent=false`, 선택 `consentVersion`.

Android는 연결된 요약이 없으면 Samsung 선택을 비활성화하고 운동 기록에서 먼저 연결하도록 안내한다. 선택 인바디 측정일은 접힌 제목에도 표시하고 화면 상태 복원 시 유지한다. 서버는 구버전 클라이언트의 요약 없는 선택을 받아도 정보를 추정하지 않고 제외 안내를 남긴다.

- 같은 ID·같은 입력의 재전송은 기존 요청을 반환한다. 다른 입력 재사용은 409, 다른 소유자·세션의 ID는 404다.
- 세션 잠금으로 동일 세션의 동시 생성을 제한한다. 진행 중 다른 ID 생성은 409다.
- 상태는 `GENERATING`, `READY`, `FAILED`, `CANCELED`. 실패·취소 후 재분석은 새 ID를 쓴다. 네트워크 응답 유실 재시도에는 기존 ID를 쓴다.
- 작업 큐는 별도 2개 스레드·8개 대기 항목. DB 트랜잭션 밖에서 AI를 호출한다. 120초 지난 요청은 실패 처리하며 늦은 결과로 덮어쓰지 않는다.
- 취소는 결과 반영을 막는다. 이미 외부에 전송된 요청의 회수를 의미하지 않는다.

응답은 `id`, `status`, `createdAt`, `result`, `message`. 결과는 `source=AI|RULE_BASED`, `summary`, `observations`, `nextActions`, `snapshot`, `methodVersion`이다. 각 항목은 `id`, `title`, `explanation`, `evidence`를 가진다. 기존 외부 API 형태를 유지한다. 내부 공급자 응답은 각 항목의 `evidenceIds`를 사용하고 서버가 실제 근거로 변환한다.

## 데이터와 저장

- 프로필 목표·헬스 숙련도는 서버에서 읽는다. 누락 시 알림과 함께 해당 해석을 제외한다.
- 현재 기본 리포트의 수행 수치와 이전 동일 운동 비교를 스냅샷으로 보존한다. 종목별 `completedSets`에 완료 세트의 중량·반복·휴식·RPE를 추가했다. 이전 저장 JSON에는 없을 수 있어 빈 목록으로 역호환한다. 서로 다른 날짜의 이전 종목 볼륨을 한 이전 세션의 합계로 단정하지 않는다.
- 인바디는 명시적으로 선택한 본인 기록의 측정일·체지방률·골격근량만 사용한다. 운동 이후 측정 및 90일 초과 과거 측정은 한계 안내를 붙인다.
- Samsung Health는 해당 세션에 연결하여 저장한 본인 요약만 사용한다. 활동 시간·칼로리·평균 심박을 최소화해 읽으며 누락 수치는 추정하지 않는다.
- FitMate 경과 시간과 Samsung Health 활동 시간은 별도 출처로 보존하며 더하지 않는다.
- V24는 `fitness_workout_insights` 테이블만 추가한다. 기존 migration·기록은 수정하지 않는다. 요청·동의 버전·스냅샷·결과·상태를 보존한다. 프로필이 바뀌어도 기존 결과는 바뀌지 않는다.
- 실패·취소 요청도 로컬에 스냅샷이 남는다. 보관·삭제 기간은 공개 서비스 전 확정이 필요하다. 기존 DB 적용과 공개 서비스 운영 승인을 혼동하지 않는다.

## 외부 AI와 동의

- 기본값 `fitmate.workout-report-ai.enabled=false`. 활성화 환경 변수 `FITMATE_WORKOUT_REPORT_AI_ENABLED`. 추천 AI 활성화와 별도다.
- 현재 공통 AI 연결 설정의 key/model/base URL을 재사용하되 호출 여부와 동의는 별도 검사한다.
- 동의 버전 `workout-insight-demo-v2`. 휴식·RPE·측정 간격과 생성 후 검토 전송을 안내한다. 이전 리포트/추천 동의로 신규 생성을 허용하지 않는다.
- 외부 전송: 목표·숙련도, 수행 수치·완료 세트별 휴식·RPE·이전 비교 수치, 선택 체지방률·골격근량·운동일 대비 측정 간격, 선택 기기 활동 시간·칼로리·평균 심박. 생성한 설명과 최소화한 근거를 두 번째 AI 호출로 검토한다.
- 이름·연락처·나이·성별·키·원본 이미지·자유 메모·사용자/세션/운동 UUID·기기 식별자·사용자 지정 운동명은 보내지 않는다. 인바디 측정일·세션 시각도 외부 입력에는 넣지 않는다.
- OpenAI Responses API의 구조화된 JSON 응답과 `store=false`를 사용한다. 이는 모든 공급자 로그가 즉시 삭제된다는 의미가 아니다. [공식 구조화 응답 문서](https://developers.openai.com/api/docs/guides/structured-outputs)를 참고했다.
- 공개 서비스용 전송·보관·삭제 정책은 미확정이며 화면에 개발·시연용임을 표시한다.

## Android

헬스 기록 상세와 운동 완료 리포트에 해석 진입점을 추가한다. 전용 전체 화면에서 정보 선택→생성→결과→재분석을 제공한다. 앱의 공통 색상, 작은 뒤로가기 헤더, 본문 제목과 하단 버튼을 재사용한다. 별도 AI 동의는 기본 해제 상태다. 앱을 나갔다 다시 열면 서버의 최신 요청을 조회한다.

상세 검증은 [검증 기록](../03-qa/운동-리포트-ai-검증-260915.md)을 따른다.
