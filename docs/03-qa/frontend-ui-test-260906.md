# Android 프론트 통합 테스트 순서

- 작성일: 2026-09-06
- 최종 수정일: 2026-09-07
- 버전: 1.9
- 상태: 검토 중
- 대상: Home-desktop 개발본 / Galaxy S26+ 실기기 확인 대기

## 검증 범위

### 알림 목록 밀도 개선 (2026-09-07)

- 개별 outlined card/삭제 버튼을 제거하고 종류별 36dp 아이콘, 작은 카테고리, 본문, 미확인 점, 얇은 구분선의 컴팩트 행으로 변경했다. 기본 최소 높이는 76dp이며 긴 내용/큰 글씨에 맞춰 확장한다.
- 행 전체를 눌러 기존 목적지로 이동한다. 개별 삭제/읽음 전환은 행 옵션, 전체 읽음/삭제는 상단 관리 메뉴, 설정은 톱니바퀴에 배치했다. 전체 삭제 확인 절차는 유지한다.
- [ ] 알림 종류별 행 밀도, 긴 본문/큰 글씨, 라이트/다크 대비 확인.
- [ ] 행 선택 시 읽음 및 목적지 이동, 개별 옵션이 목적지 이동을 유발하지 않는지 확인.
- [ ] 읽음/미확인 전환, 개별 삭제, 모두 읽음, 전체 삭제 취소/확인, 빈 상태와 설정 열기 확인.

### 사용성 애니메이션 (2026-09-07)

- 화면 진입은 180ms 페이드와 짧은 이동, 하단 탭은 페이드만 적용한다. 이전 화면을 동시에 유지하지 않아 운동 화면의 타이머/효과가 중복 실행되지 않도록 했다.
- 홈 퀵 액션·운동 시작·공통 주요 버튼은 누를 때 살짝 축소된다. 좋아요는 선택 순간에만 짧게 확대 후 복귀하며, 이미 선택된 글의 첫 표시에는 재생하지 않는다.
- 프로필 탭 표시 색, 게시물 그리드 높이, DM 항목 추가/삭제/이동, 오류 안내 펼침/접힘, 운동 진행률을 부드럽게 전환한다. 기존 Material 모달 효과는 유지한다.
- 검증: assembleDebug 및 testDebugUnitTest 성공(33개, 실패 0). Galaxy에 업데이트 설치 후 운동 선택 진입/뒤로가기·프로필/DM 탭 전환을 확인했다.
- [ ] 홈 카드와 운동 시작 버튼의 눌림 반응, 빠른 반복 탭과 뒤로가기 확인.
- [ ] 좋아요 선택/해제, 프로필 게시물/운동 기록 탭 전환 확인.
- [ ] DM 짧은/긴 메시지 전송·삭제 시 말풍선 전환과 키보드/하단 스크롤 확인.
- [ ] 입력 오류 표시/해제, 운동 세트 완료 후 진행률과 휴식 타이머 확인.
- 세트 기록/수정 성공 시 버튼 완료 문구가 짧게 전환되고 해당 기록 행에 민트 강조가 들어간다. 약 1.4초 후 기본 문구로 돌아오며, 복원된 기록에는 재생하지 않는다.
- [ ] 세트 신규 기록/수정/연속 기록 시 완료 문구와 행 강조, 잘못된 입력 시 성공 효과 미표시, 휴식 시작 및 수정/삭제 후 강조 초기화를 확인한다.
- [ ] 라이트/다크, 시스템 애니메이션 제거 설정, 큰 글씨/TalkBack에서 회귀 확인. 애니메이션의 체감 속도·잔상·실기기 프레임 성능은 사용자 확인 및 추가 측정 대상이다.

러닝·메이트·커뮤니티/DM·인바디의 프론트 UI와 앱 실행 중 상태 연결을 구현했다. Spring Boot API, 서버 업로드/OCR, 상대 기기와의 통신은 연결하지 않았다. 러닝은 위치 권한을 받은 뒤 Android 위치 API를 사용하는 포그라운드 서비스로 거리·시간·페이스·랩을 기록한다. 지도·경로 저장·백그라운드 위치 권한·강제 종료 후 GPS 재개는 포함하지 않는다. Samsung Health는 SDK에서 읽어 온 최근 7일 운동의 제공 값을 헬스 리포트에서 참고 표시한다.

사진 선택은 Android Photo Picker, 촬영은 카메라 앱과 FileProvider를 사용한다. 실제 사진을 선택·촬영하지만 서버에 전송하지 않는다. 파일 저장 권한이나 전체 갤러리 접근 권한은 요청하지 않는다.

최신 개발본은 단일 로컬 데모 프로필, 사진 URI, 헬스/러닝 기록과 임시 운동, 저장 루틴, 건강/위치 동의 설정을 앱 전용 저장소에 보관한다. 커뮤니티 게시물·댓글·작성 초안, DM·입력 초안, 팔로우/차단, 신고/알림, 메이트 모집/참가/평가 상태, 저장 완료한 인바디 기록도 로컬 보관한다. 서버 통신은 여전히 Mock이다. 클라우드/기기 백업 대상에서 제외하며 비밀번호·토큰은 저장하지 않는다. 약 1초 간격 및 백그라운드 전환 시 저장하고 운동은 일시정지로 복원한다. 갑작스러운 프로세스 종료 직전 변경은 일부 유실될 수 있다. 사진은 URI만 보관하므로 원본 삭제·접근 권한 상실 시 재선택해야 한다. 저장 전 인바디 입력/판독 진행과 메이트 작성 초안은 복원 범위에 포함하지 않는다.

## 로컬 보관·날짜 기록 1차 보강

- 신규 완료 운동부터 완료 시각을 저장한다. 프로필 운동 기록에서 종목 혼합 최신순·월별 필터를 제공하고, 기존 무날짜 기록은 날짜 없음으로 유지한다.
- 전송 중 중단된 DM은 복원 시 전송 실패로 표시한다. 동일 메시지 재전송은 가능하지만 새로운 요청 메시지 제한은 유지한다.
- 운동 버튼 최소 높이 48dp, 스위치 행 전체 터치와 의미 정보, 오류 문구 live region을 적용했다. 큰 글씨·TalkBack 전체 검증은 미실행이다.
- 검증: Debug 빌드·단위 테스트 33개 통과(복원/기존 형식/날짜 정렬/메이트 상태 및 실제 GPS 랩 계산). Galaxy에서 게시물과 작성 초안을 만든 후 홈 이동 → 강제 종료 → 재실행해 두 내용이 유지됨을 확인했다.
- 후속 확인: DM 입력·메시지/차단/메이트/인바디 저장 → 재실행, 사진 원본 접근 실패, 신규 운동 완료 날짜·월별 필터, 삭제한 기록의 재등장 방지, 큰 글씨·TalkBack, 동의 철회·탈퇴. 삭제/탈퇴 테스트는 마지막에 진행한다.
- 위치·알림 권한을 사용자가 허용한 실외 GPS 거리 검증과 큰 글씨/TalkBack·사진 실패 전체 회귀는 아직 수행하지 않았다. 개발·테스트 상태 조작 UI는 Release 빌드에서 숨긴다.

## 잔여 프론트 6영역 구현 후 확인 순서

### 프로필·운동 기록 UI 후속 확인

- 홈 운동 시작 → 헬스 시작 → 루틴 선택/새 루틴 만들기: 검정 대신 채도를 낮춘 기존 민트·그린 계열 버튼을 확인한다.
- 내 프로필과 타인 프로필: 동일한 아바타/운동 기록/팔로워/팔로잉 행, 소개, 2개 행동 버튼, 게시물/운동 기록 탭 및 게시물 그리드를 확인한다. 타인 통계 미수신은 `—`로 표시하며 내 팔로우 수를 상대 통계로 사용하지 않는다.
- 프로필 → 운동 기록: 내 기록이 기본이다. 전체/헬스/러닝 필터, 빈 상태, 카드 전체 클릭으로 세트·RPE·메모·이전 동일 운동 비교 또는 러닝 구간 상세를 확인한다.
- 예시 보기 → 헬스 2건/러닝 1건 → 내 기록으로: 예시와 실제 데이터가 분리되고 프로필 통계가 바뀌지 않는지 확인한다. 저장 날짜가 없는 기존 기록은 날짜를 추정하지 않고 종목별 최근 저장 순으로 표시한다.
- 타인 프로필의 사용자 옵션에서 신고/차단/팔로우 요청 응답 예시를 확인한다. 운동 기록 탭은 열람 가능한 게시물에 첨부된 기록만 표시한다. 뒤로가기로 원래 진입 화면에 복귀한다.

### 기존 기능 회귀 확인

실제 인증/이메일 발송/Push/서버 삭제는 수행하지 않는 UI 데모다. 실제 개인정보·비밀번호 대신 테스트 값을 사용한다. 약관과 개인정보 처리방침은 검토용 안내이며 확정 문구가 아니다.

1. 최초 실행 → 로그인 → 회원가입. 이메일 `preview@naver.com`, 중복 확인 → 코드 받기 → `123456` → 인증 확인. `used@example.com`은 중복 예시, 다른 코드/3분 초과는 오류, 재발송은 인증 상태를 초기화한다. 테스트 비밀번호는 영문·숫자 포함 8자 이상(예: `DemoOnly123`)이다.
2. 이름/생년월일/성인 확인 → 닉네임 중복 확인(민준·수연·지현은 사용 중 예시) → 운동 정보 → 약관 상세 → 동의 후 가입. 로그인 오류/정지/네트워크 오류는 로그인 화면 개발 도구에서 전환한다.
3. 프로필 → 설정 → 계정·개인정보 관리: 비밀번호 변경/재설정의 인증·불일치·성공 예시, 로그아웃 후 동일 로컬 이메일 로그인, 약관/정책, 동의 철회 확인. 인바디는 건강정보 동의가 없으면 안내 후 동의해야 진입한다.
4. 프로필 설정에서 사진 선택/제거. 프로필의 사용자/팔로워/팔로잉 → 다른 사용자 프로필. 비공개 메이트 팔로우 → 요청 취소/재요청 → 수락 받기/거절 받기. 승인 전 프로필 상세·DM 제한, 승인 후 일방 팔로워는 DM 요청, 맞팔은 일반 대화를 확인한다. 설정의 팔로우 요청 관리에서 받은 요청을 수락/거절한다.
5. 홈 → 운동 시작 → 헬스: 기본 루틴의 실제 운동 목록, 수정해서 저장, 저장 루틴 편집/정렬/삭제, 새 루틴 만들기, 저장 없이 직접 구성을 확인한다. 기본 루틴은 고정 예시이며 개인 맞춤 AI 추천이 아니다.
6. 운동 중: 운동 설명·대체, 현재 구성 루틴 저장, kg/lb 전환 및 기록. 완료 후 다시 같은 운동 시작 → 이전 동일 운동 기록 불러오기. 프로필 운동 기록 탭 → 헬스 기록 상세·비교.
7. 헬스 진행 중 홈 버튼으로 앱 백그라운드 전환 → 앱 강제 종료 → 재실행 → 홈의 운동 이어하기를 확인한다. 러닝 실제 GPS 기록 중에는 포그라운드 알림을 확인하고 홈으로 전환한 뒤에도 시간·거리 기록이 이어지는지 확인한다. 강제 종료 시 GPS 서비스는 종료되며 재개하지 않는다. 저장 루틴과 완료 기록도 재실행 후 유지되는지 확인한다.
8. 홈 알림 또는 프로필 설정 → 알림: 빈 상태, 개발 도구의 예시 알림 생성, 읽음/모두 읽음/삭제, 종류별 화면 이동 및 전체/종류별 Push 설정 확인. 실제 OS Push 권한·전송은 미연결이다.
9. 타인 게시물 ⋯ → 게시물 신고 또는 타인 프로필 → 프로필 신고 → 사유/내용 입력 → 로컬 접수. 프로필 설정 → 내 신고 내역에서 처리 결과 시뮬레이션과 알림 확인.
10. 데이터 삭제/탈퇴는 마지막에 테스트한다. 로컬 헬스 기록 삭제 확인/취소, 로그아웃은 보관 유지, 탈퇴 확인은 데모 로컬 프로필·루틴·운동 기록 초기화 및 로그인 화면 복귀. 서버 데이터·사용자의 원본 갤러리 사진을 삭제하지 않는다.

UI/Mock 구현과 자동 테스트 통과를 기능명세 전체·실서비스 완료로 해석하지 않는다. 실제 API/AI/GPS/권한/보안/운영 정책과 전체 실기기 회귀 검증은 별도다.

### 이번 자동/실기기 확인 결과

- 단위 테스트 27개 통과: 이메일/테스트 비밀번호 검증, kg/lb 정규화, 스냅샷 JSON 왕복/세션 복원, 러닝 랩 복원, 비공개 프로필/DM 승인 제한, 취소·차단 요청의 늦은 수락 방지, 발신 요청 처리 포함.
- Galaxy에서 새 회원가입의 이메일 인증/닉네임 중복 확인 및 홈 진입 확인.
- 여러 운동으로 구성된 루틴 진입 후 1세트 기록 → 일시정지 → 백그라운드 → 강제 종료 → 재실행. 1세트·360kg·16초가 일시정지 상태로 복원됨을 확인. 30kg→66.14lb 입력 표시 확인.
- 비공개 프로필 승인 전 상세 숨김 → 팔로우 요청 → 수락 예시 후 상세/DM 요청 노출 확인.
- 프로필 신고 로컬 접수 → 신고 내역 RECEIVED → RESOLVED 시뮬레이션 → 생성된 알림 선택 시 해당 신고 내역 이동 확인.
- 사진 선택/장기 URI 접근, 모든 로그인 오류/재설정 분기, 루틴 편집·재실행 전체, 러닝 실기기 복원, 동의 철회/삭제/탈퇴 전체 회귀는 사용자 추가 확인 대상이다.

## 자동 검증

- `android` 폴더에서 `.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest` 실행.
- 인바디 실제 날짜·미래 날짜·NaN·범위·선택 항목 검증.

## 실기기 테스트

### UI/UX 2차 수정 및 회귀 확인

- Debug 빌드 및 단위 테스트 18개 통과(운동 입력 검증·일시정지 상태 보존·초안 초기화 테스트 3개 추가).
- Galaxy에서 홈 `+` → 작성창 직접 진입, 테스트 본문 입력 → 뒤로 닫기 → 다시 열기 시 초안 복원, 명시적 초안 삭제 확인.
- `내 게시물` → 프로필 → 인바디 기록 → 시스템 뒤로가기 시 프로필 복귀, 커뮤니티 재진입 시 빈 내 게시물 탭 유지 확인.
- 헬스 직접 구성 → 운동 미추가 상태의 세트 기록 차단 → 운동 추가 → 1세트 기록 → 상단 뒤로가기 → 잠시 나가기 → 홈의 운동 이어하기 확인. 1세트·360 kg·37초 및 남은 휴식 84초가 보존됨을 확인했다. 시스템 뒤로가기에서도 확인 대화상자가 나타났다.
- 테스트용 운동은 안전 안내의 운동 취소로 종료했다. 서버 저장이나 실제 운동 기록을 만들지 않았다.
- DM 짧은 메시지의 내용 폭 말풍선, 메시지 선택 시 삭제 메뉴, 대화 옵션 시트를 확인했다. 사진 촬영·전송 실패 등 전체 회귀는 이번 수정 후 재실행하지 않았다.
- 홈 중복 시작 버튼 제거, 피드 여백 축소, 메이트/DM 목록 압축, 중복 화면 제목 제거, 선택 칩 민트 색상 적용.
- 상태 보존은 같은 앱 실행 중 화면 이동 범위다. 재설치·프로세스 종료 후 운동/초안 복원은 지원하지 않는다. 운동 이어하기는 일시정지 상태로 돌아오므로 `재개`를 눌러 타이머를 시작한다.

사용자 재확인 순서:

1. 홈 → `+` → 본문 작성 → 키보드를 닫고 다시 뒤로 → `+`: 초안 유지. `초안 삭제` → 확인 시에만 폐기.
2. 커뮤니티 → `내 게시물` → 다른 하단 탭 → 커뮤니티: 탭/스크롤 유지.
3. 프로필 → 인바디 기록 → 뒤로: 홈이 아닌 프로필로 복귀.
4. 홈 → 운동 시작 → 헬스 → 직접 구성 → 운동 시작: 운동 추가 전 세트 기록 오류 안내.
5. 운동 추가 → 세트 기록 → 뒤로 → 잠시 나가기 → 운동 이어하기: 세트/시간/휴식 확인 → 재개.
6. DM → 대화: 짧은/긴 메시지, 말풍선 선택(또는 길게 누르기)의 삭제/신고, 입력 왼쪽 `+` 사진 첨부, 우측 `⋯` 대화 옵션 확인. 테스트 도구는 대화 옵션 안에 있다.
7. 메이트: 상단 `+` 모집 작성, 목록 행 선택으로 상세 진입. 민트 선택 칩과 목록 간격 확인.

### 소셜 스타일 1차 UI 적용 후 확인

- 홈: 화이트 바탕, 검정 아이콘, 원형 바로가기, 운동 시작 영역, 커뮤니티와 상태를 공유하는 피드.
- 커뮤니티: 우측 상단 `+`로 작성 시트 열기, 좋아요/댓글 아이콘, `⋯` 메뉴의 수정·삭제·팔로우·차단, 댓글 바텀시트.
- 프로필: 통계·소개, 프로필 편집/인바디 버튼, 게시물 3열 그리드/운동 기록 탭, 우측 `≡` 설정 시트.
- 기존 `홈 → 오늘의 운동` 진입은 `홈 → 운동 시작`으로 변경. 커뮤니티 작성 버튼은 상단 `+`, 맞팔 테스트 도구는 하단 `개발 및 테스트 도구` 시트로 이동.
- Galaxy SM-S947N에 최신 Debug 설치 후 테스트용 로컬 프로필로 온보딩, 홈 표시, 댓글 시트 이동, 텍스트 게시물 작성, 프로필 게시물 수/그리드 표시 및 상세 열기를 확인했다. 이미지 선택·그리드 크롭 및 모든 기존 기능의 재검증은 아직 수행하지 않았다.
- 이번 디자인 확인에는 실제 개인정보·계정을 사용하지 않았으며 서버 전송 없이 로컬 테스트 글을 작성했다.
- `:app:assembleDebug :app:testDebugUnitTest` 성공. 단위 테스트 15개 통과.

### 2. 러닝 설정과 진행

- [ ] 홈 → 오늘의 운동 시작 → 운동 선택 → 러닝. 헬스 세트 화면이 아니라 러닝 설정이 열려야 한다.
- [ ] 자유·거리·시간·페이스·인터벌을 차례로 눌러 필요한 설정만 나타나는지 확인.
- [ ] 거리 입력을 빈 값/0으로 바꾸고 시작 → 오류 표시. 1 km로 수정하면 시작 가능.
- [ ] `테스트용 예시 GPS 사용` ON → 시작 → `6분 진행 (+1 km, 정상 GPS)` → 거리 1 km 증가 및 1 km 랩 생성 확인.
- [ ] 일시정지 중 시간·거리 정지, 재개 후 증가 확인.
- [ ] `정지 감지` ON + 자동 일시정지 ON이면 시간·거리 정지. 정지 감지를 끄면 재개.
- [ ] GPS를 `끊김`/`권한 없음`으로 바꾸면 거리는 고정되고 시간은 유지. `정상` 복구 후 거리 증가.
- [ ] 종료 → 거리·시간·평균/최고 랩 페이스·목표 결과·구간 기록 확인 → RPE/컨디션/메모 입력 → 저장.
- [ ] 다시 러닝에 들어가 저장한 러닝 확인. 동일 거리를 다시 저장하면 이전 기록 비교 확인.
- [ ] 진행 도중 상단 뒤로가기/시스템 뒤로가기 → 취소 확인. 계속하기(대화상자 취소)를 누르면 기록 유지, 나가면 미저장 기록 폐기.
- [ ] 예시 GPS OFF로 시작하면 실제 거리가 임의로 늘어나지 않고 데이터 없음 상태가 표시되어야 한다.
- [ ] `테스트용 예시 GPS 사용`을 끄고 러닝 시작 → 위치 사용 안내를 확인 → 사용자가 위치/알림 권한을 허용한다. 포그라운드 알림이 표시되고 GPS 정확도 대기 후 거리·페이스가 움직이는지 실외에서 확인한다.
- [ ] 실제 GPS 기록 중 홈으로 이동 → 알림이 유지되고 1~2분 뒤 앱으로 돌아왔을 때 시간·거리가 계속 누적되는지 확인한다. 일시정지/재개/운동 종료 시 알림과 위치 업데이트가 중지되는지 확인한다.
- [ ] 실제 GPS는 포그라운드 서비스 범위다. 강제 종료·권한 거부·GPS 비활성화 시 기록이 재개되지 않거나 안내가 표시되는지 확인한다. 경로 지도와 좌표 저장은 제공하지 않는다.

- [ ] 확정 참가자 목록 → DM 진입 확인.
- [ ] 기존 `오늘 저녁 헬스 같이 해요` 글 → 미확정일 때 정확한 집결 위치 숨김 확인 → 신청 → 취소 → 재신청 → `수락 받기`.

- [ ] `테스트: 운동 완료 상태`로도 평가 화면 확인 가능. 시간 약속/매너/내용 일치/다시 함께할 의향을 선택하고 비공개 메모 저장 → 평가 완료·재제출 불가.
- [ ] 별도 모집글에서 모집 마감/재개, 모임 취소 확인 대화상자 확인. 취소 후 신청 불가.

- [ ] 촬영 → 카메라 촬영/확인 → 선택 사진 표시. 카메라/갤러리 취소 후 앱이 정상 유지되는지 확인.
- [ ] Debug 빌드에서 `테스트: 판독 실패 재현` ON → 실패 안내 → OFF 후 재판독, 재촬영/사진 재선택, 직접 입력 전환 확인.
- [ ] 헬스 세트 기록 시작 전 Samsung Health 사용을 선택 → 종료 후 리포트의 `동기화 새로고침`으로 최근 7일 운동의 거리·칼로리·평균 심박 표시를 확인한다. 권한이 없으면 `연결 관리`에서 Samsung Health 읽기 권한을 요청한다. 서버 매칭 전이므로 FitMate 세션에 원본 데이터를 자동 병합하지 않는다.
- [ ] 진행 도중 취소 → 늦게 완료된 판독이 화면을 다시 열거나 기록을 저장하지 않는지 확인.
- [ ] 의료 진단이 아닌 운동 기록 안내가 표시되는지 확인.

## 후속 연동 범위

실외 실제 GPS 거리·페이스 정확도, 지도/경로 저장, 강제 종료 후 GPS 재개, Samsung Health 원본 세션과 FitMate 세션의 서버 기반 매칭, 이미지 업로드/OCR, 실제 요청·수락·차단 권한 검증, 서버 동기화는 별도 연동 작업이다. 프론트의 테스트 도구는 서버 응답이 없는 상태에서 UI를 확인하기 위한 수단이며 Release 빌드에는 노출하지 않는다.
