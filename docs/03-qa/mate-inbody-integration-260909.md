# 메이트·인바디 Android 연동 검증

- 작성일: 2026-09-09
- 최종 수정일: 2026-09-09
- 버전: v0.5
- 상태: 실기기 자동 검증 완료 (실사용 결과표 검증 별도)
- 기준: main 494b657 이후 작업, codex/connect-inbody-api
- 기기: Samsung SM-S947N, Android 16, USB debugging

## 구현 범위

### 메이트

- V19 migration으로 집결 위치, 공개 범위, 종목별 상세 조건, 초보 환영 여부를 저장한다.
- 집결 위치는 목록에 노출하지 않고 작성자·확정 참가자의 상세에서만 공개한다. 맞팔·차단은 서버 목록/상세/신청/문의에서 검사한다.
- Android 목록·더 보기·작성·상세·제목/안내 수정·참가 신청·수락/거절·참가 취소·모집 마감/취소·문의방 목록/메시지/읽음을 실제 API에 연결했다.
- 서버 UUID로 화면·요청 대상을 식별한다. 빈 응답이나 실패를 Mock 모집글로 대체하지 않는다.
- 생성 요청은 같은 입력 재시도에 같은 Idempotency-Key를 사용한다. 인증 갱신 후에도 이 헤더를 유지한다.
- 문의 메시지는 재전송 시 동일 clientMessageId를 사용하며 sequence 기준으로 중복 제거·추가 조회한다.
- 작성 화면은 서버 활성 종목만 선택할 수 있다. 지역을 선택하고 기기 현지 시각을 Instant로 변환한다.
- 메이트 알림의 MATE_POST/MATE_CHAT_ROOM 대상을 UUID 상세·문의 화면으로 연결했다. 알림 탭 동작은 별도 실기기 자동 테스트에 포함하지 않았다.

### 인바디

- 기존 촬영/사진 선택 → INBODY 업로드 → 분석 생성 → polling → 검수 → 서버 저장 → 목록/최근 3개/차트/삭제 흐름을 연결했다.
- 직접 입력·새 사진 선택 시 이전 analysisId를 초기화한다.
- 누락 수치는 임의로 채우지 않으며, 재확인 항목과 서버 Mock 판독 여부를 안내한다.
- 필수 수치 및 선택 항목을 서버 코드로 매핑한다. 음수 체중 조절 수치도 허용한다.
- 판독 지연·네트워크 오류는 같은 ID의 상태를 다시 조회하고 FAILED일 때만 retry한다.
- 화면에서 기다리기를 그만둬도 서버 작업은 취소되지 않음을 표시한다.
- 판독 생성 응답을 잃으면 중복 분석을 자동 요청하지 않는다. 저장 응답이 불명확하면 반복 저장을 막고 목록 확인을 안내한다.
- Gemini 오류 응답 원문 및 공급자 예외 체인을 로그에 남기지 않도록 보완했다.

실기기 테스트 MateInbodyDeviceTest:

1. 추가 필드·집결 위치 권한, 생성 멱등, 신청/수락/철회/거절, 채팅 멱등/읽음, 상세 화면 수정, 마감/취소.
2. 맞팔 전 비노출·404, 양방향 팔로우 후 노출, 차단 후 비노출·신청 차단.
3. 모집 작성 화면 입력·게시, 문의 진입·메시지 전송·상대 답장 표시.
4. 직접 입력 화면 저장, 서버 최근 기록/변화 표시·삭제 갱신, 합성 이미지 업로드와 서버 Mock 판독, 검수 수정 후 AI_OCR 기록 저장.

Mock 판독 테스트는 **Android↔서버↔MySQL 왕복 검증**이다. 실제 Gemini의 이미지 인식 정확도 검증은 아니다. 갤러리 시스템 선택창·카메라 실촬영·실제 결과지 인식, 네트워크 단절/장시간 timeout 전체 조합은 이번 자동 테스트 범위에 포함하지 않았다.

## 실행 및 안전

- 개인 앱 데이터와 분리된 com.fitmate.app.dev.records 테스트 앱을 사용했다. 합성 계정·모집글·인바디 기록만 생성했다.
- 일반 com.fitmate.app.dev 앱은 기존 서명과 현재 PC debug 서명이 달라 덮어쓰지 못했다. 최신 기능의 실기기 검증은 별도 테스트 앱에서 수행했으며 기존 일반 앱은 이전 버전이다.
- 테스트 종료 후 최신 com.fitmate.app.dev.records APK를 다시 설치·실행했다. 일반 앱을 업데이트하려면 기존 debug 서명키가 필요하며, 데이터 삭제를 수반하는 제거·재설치는 승인 없이 하지 않는다.
- 기존 FitMate 전용 MySQL 컨테이너를 재시작했다. 다른 프로젝트 DB는 변경하지 않았다.
- 로컬 개발 DB에 합성 테스트 데이터가 남아 있다. 기존 사용자 데이터·Gradle wrapper·비밀 설정 파일은 변경하지 않았다.
- local.properties 및 application-local.yml의 내용을 열람하거나 키를 출력하지 않았다.
- 처음에는 default 프로필로 실행해 PROVIDER_NOT_CONFIGURED가 발생했고 이 단계에서는 외부 호출이 없었다. 사용자가 지정한 application-local.yml은 local 프로필 활성화로 적용했다.
- local 프로필 서버는 DB URL을 기존 FitMate 전용 localhost:3307/fitmate로 고정했다. 서버가 V19를 재검증했다.
- 이전 승인 호출 일부는 HTTP 503 / PROVIDER_UNAVAILABLE로 종료됐다. Google API 호스트 TCP 443 연결은 성공했다.
- 이후 backend GeminiInbodyLiveTest를 local 프로필·합성 결과표로 다시 실행해 성공했다. 이 테스트는 Android, HTTP controller, DB를 거치지 않고 GeminiInbodyAnalyzer만 호출하며 체중 68.2kg, 골격근량 29.4kg, 체지방률 18.5% 인식 결과를 검증한다.
- 사용자 승인 후 USB 실기기에서 합성 결과표로 실제 Gemini end-to-end를 1회 실행해 성공했다. Gemini가 체중 68.2kg, 골격근량 29.4kg, 체지방률 18.5%를 반환했고, Android 검수 화면에서 체중을 68.3kg으로 수정한 뒤 AI_OCR 기록으로 저장됨을 API로 확인했다.
- 추가 유료 분석은 자동 수행하지 않는다. 실패 테스트를 성공 또는 Mock 대체 성공으로 집계하지 않는다.

Android 단위·빌드:

    cd android
    .\gradlew.bat testDebugUnitTest assembleDebug

별도 테스트 앱의 실기기 검증 (서버 provider=MOCK 필수):

    .\gradlew.bat '-PfitmateIsolatedTest=true' '-Pandroid.testInstrumentationRunnerArguments.class=com.fitmate.app.ui.MateInbodyDeviceTest' '-Pandroid.testInstrumentationRunnerArguments.mateInbody=mock' connectedDebugAndroidTest

Backend 단위·계약 회귀:

    cd ../backend
    .\gradlew.bat test --tests '*Mate*' --tests '*Inbody*'

## 사용자가 확인할 순서

1. 로그인 → 홈 → 메이트: 실제 모집 목록·빈 상태·새로고침 확인.
2. 모집 글 작성: 활동 지역/종목/날짜·시간/집결 위치/공개 범위/세부 조건 입력 후 게시.
3. 내 모집 상세: 제목·안내 수정, 신청 관리, 받은 문의 채팅 확인.
4. 다른 계정: 상세에서 집결 위치가 숨겨지는지, 신청 수락 뒤 보이는지 확인.
5. 문의 채팅: 짧은/긴 메시지, 상대 답장, 읽음 표시 확인.
6. 홈 → 인바디 → 직접 입력: 날짜·체중·골격근량·체지방률 저장, 최근 기록/변화 확인.
7. 인바디 사진 선택/촬영 → 검수: 합성 결과표 기준 실제 AI 분석·수정·저장까지 자동 검증했다. 실제 사용자 결과표는 사진 품질·양식별로 별도 확인할 것.

## 후속 UI 개선 및 재검증

- 인바디 검수·저장 기록 상세를 독립 페이지로 통일하고 요약, 체지방, 부위별 근육량·지방량, 목표 및 추가 항목으로 구분했다.
- 라이트 모드 카드 테두리 대비를 높이고 근육량·지방량의 실루엣과 꺾인 연결선, 양쪽 수치 간격을 실기기에서 확인했다. 신체 그림은 실제 체형 판정이 아닌 항목 구분용이다.
- 사용자 승인으로 로컬 사진 판독 기록 한 건의 비어 있는 부위별 지방량 5개에 UI 확인용 예시값을 추가했다. 실제 AI 판독값이 아니며 DB 예시값·스크린샷은 Git에 포함하지 않는다.
- 홈·커뮤니티 게시글 시간을 기기 시간대 기준 `yyyy-MM-dd HH:mm`으로 표시한다. UTC 변환, 소수 초 제거, 연도 경계 등을 단위 테스트하고 두 화면의 실제 서버 게시글 표시를 확인했다.
- PR 준비 시 Android 단위 테스트·debug 빌드와 Backend Mate/Inbody 테스트를 다시 실행했다. 유료 Gemini 및 전체 실기기 자동 테스트는 재실행하지 않았으며 위 자동 검증은 이전 실행 결과다.
- 백엔드 중단 후 local 프로필로 재기동하여 health HTTP 200과 실기기 세션·게시글 조회 복구를 확인했다. 이번 중단 원인은 확인되지 않았다.

## 남은 검증·제약

- 실제 사용자 결과표의 다양한 양식·촬영 품질에 대한 인식 검증.
- 인바디 분석 생성 응답 유실 시 ID 복구 및 직접 입력 저장의 서버 멱등 계약은 아직 없다. 자동 재시도 대신 사용자 확인으로 중복 호출을 방지한다.
- 앱 프로세스 종료 뒤 진행 중인 인바디 analysisId 복원은 구현하지 않았다.
- Backend 별도 테스트 DB의 기존 통합·동시성 테스트 19개는 미실행이다.
- PR 생성·merge는 사용자 승인 후 진행한다.
