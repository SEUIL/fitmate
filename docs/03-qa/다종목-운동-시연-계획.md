# 다종목 운동 시연 계획

- 작성일: 2026-09-14
- 최종 수정일: 2026-09-14
- 버전: v1.0
- 상태: 확정
- 대상: 배드민턴·클라이밍·등산·골프 개인 운동 시연
- 검증 상태: 계획만 작성. 아래 항목은 미실행

## 1. 목표와 시간

신규 네 종목을 실제 백엔드·DB로 기록하고 재조회하는 흐름을 보여 준다. 배드민턴은 현장에서 시작부터 저장·재조회까지 수행하고, 나머지는 미리 저장한 예시 기록으로 종목별 차이를 설명한다. 신규 종목 구간은 약 2~3분이다.

승인과 후속 Action Item은 [결정·회의 로그](../00-project/결정-회의-로그.md)의 `2026-09-14 다종목 개인 운동 시연 범위 확정`을 따른다. 구현 범위는 [백엔드](../02-technical/다종목-운동-백엔드-구현-계획.md), [DB](../02-technical/다종목-운동-db-구현-계획.md), [프론트](../02-technical/다종목-운동-프론트-구현-계획.md) 계획에 있다.

[기존 15분 발표 시나리오](./15분-발표-시연-시나리오.md)는 변경하지 않는다. 15분을 유지할 경우 헬스 구간의 운동 추가·대체·순서 변경 설명에서 약 1분, 커뮤니티 사진 수정·DM 설명에서 약 1분 30초를 줄여 이 구간을 배치하는 것을 발표 편집 기준으로 사용한다. 기존 필수 시연을 포함한 전체 시간은 최종 리허설에서 확인한다.

## 2. 시연 전 준비

- 신규 migration과 백엔드, Android가 같은 API 계약으로 연결된 개발 환경을 준비한다.
- 발표 계정의 헬스·러닝 기존 기록을 유지한다. 네 종목이 개인 운동 선택에서 보이는지 확인한다.
- 아래 예시를 앱 또는 API로 실제 서버에 저장한다. migration seed나 프론트 하드코딩 응답으로 대체하지 않는다.
- 예시 메모에는 `기능 시연용 예시 기록`을 넣는다. 가상의 결과이며 실제 운동 측정값처럼 설명하지 않는다.
- 각 기록을 화면에서 다시 열어 결과가 보이는지 확인하고 동일 계정으로 앱 재실행 후 재조회한다.
- 배드민턴 예시도 하나 준비해 현장 저장 실패 시 조회 대체용으로 사용한다.

| 종목 | 사전 예시 | 보여 줄 차이 |
|---|---|---|
| 배드민턴 | 복식, 운동 20분, 3게임·2승 | 게임 수와 승리 수 |
| 클라이밍 | 볼더링, 운동 30분, 8회 시도·5회 완등, 난이도 메모 `체육관 파란색` | 완등 결과와 자유 메모 |
| 등산 | 등산, 운동 60분, 가상 코스명, 거리 3.2km | 수동 코스·거리 기록 |
| 골프 | 스크린, 운동 30분, 진행 9홀·총 45타 | 라운드 요약 |

시작/종료 시각은 실제 운동 시간 이상의 간격으로 설정한다. 준비용 API 입력으로 만든 기록은 사전 생성한 예시라고 설명한다. 실제 계정 식별자·토큰·비밀번호는 문서에 기록하지 않는다.

## 3. 현장 시연 순서

| 시간 | 화면 동작 | 설명 |
|---|---|---|
| 0:00–0:20 | 개인 운동 선택에서 네 종목 확인, 배드민턴 복식 선택 | 종목별 개인 기록을 지원함 |
| 0:20–0:50 | 시작 → 잠시 진행 → 일시정지 → 재개 → 종료 | 공통 타이머, 휴식 제외 시간 |
| 0:50–1:20 | 게임 1, 승리 1, 시연 메모 입력 후 저장 | 결과는 직접 입력하는 기능 시연 예시임 |
| 1:20–1:40 | 기록 목록 → 배드민턴 필터 → 방금 저장한 상세 | 서버에 저장한 값을 다시 조회함 |
| 1:40–2:40 | 클라이밍·등산·골프 필터와 준비된 상세 확인 | 종목별 결과 항목 차이 |
| 2:40–3:00 | 전체 목록으로 복귀 | 헬스·러닝과 함께 개인 기록 관리 |

현장 타이머는 실제 경과 시간을 사용하고 짧은 초 단위 기록도 저장할 수 있게 한다. 시간을 가속하거나 실제 운동 20분을 측정한 것으로 바꾸어 표시하지 않는다.

발표 문장 예시:

> 배드민턴, 클라이밍, 등산, 골프도 같은 흐름으로 운동 시간을 기록할 수 있습니다. 운동을 마치면 종목에 맞는 결과를 직접 입력하고, 저장한 기록을 다시 확인합니다. 지금은 짧은 시연과 예시 결과로 저장 과정을 보여드리겠습니다.

등산 설명에서는 거리 수동 입력임을 밝힌다. 신규 종목의 GPS·지도·Fit3·Samsung Health 연결, 전문 분석·자동 칼로리, 메이트에서 개인 기록 시작은 시연하지 않는다.

## 4. 해당 기능만 확인하는 체크리스트

아래는 후속 구현 완료 후 수행할 항목이다. 이번 문서 작성에서는 체크하지 않는다.

- [ ] 네 종목 각각 시작·일시정지·재개·종료·저장·재조회가 된다.
- [ ] 네 종목 모두 결과 수치를 비워도 시간 기록을 저장할 수 있다.
- [ ] 배드민턴 승리 ≤ 게임, 클라이밍 완등 ≤ 시도 조건을 확인한다.
- [ ] 골프 연습/스크린/필드 전환 시 다른 유형 결과가 전송되지 않는다.
- [ ] 등산 3.2km 저장 후 상세에 같은 거리로 표시한다.
- [ ] 활동 시간에 일시정지가 포함되지 않고 화면 이동·회전 후 유지된다.
- [ ] 저장 전 앱 재진입 시 해당 사용자의 초안을 복원한다.
- [ ] 저장 실패·응답 유실 후 같은 ID로 재시도해 기록이 하나만 남는다.
- [ ] 다른 사용자로 로그인하면 기존 사용자의 초안·기록을 볼 수 없다.
- [ ] 전체·종목별 목록의 더 보기와 필터 전환에 누락·중복이 없다.
- [ ] 프로필 완료 개수가 저장한 세션 수만큼 증가하며 중복 합산하지 않는다.
- [ ] 라이트/다크·숫자 키보드 표시에서 입력과 저장 버튼을 사용할 수 있다.
- [ ] 기존 헬스·러닝 기록을 변경된 목록에서 각각 한 건 열 수 있다.

자동 검증은 신규 API·migration·시간/입력 상태와 직접 변경된 목록 관련 테스트만 지정한다. 인바디·소셜 등 무관한 기능과 전체 회귀 테스트를 완료 조건으로 추가하지 않는다.

## 5. 장애 대응

| 상황 | 현장 대응 | 확인할 점 |
|---|---|---|
| 저장이 늦거나 응답 유실 | 진행 안내 유지, 동일 ID 조회/재시도로 확인 | 새 기록을 다시 만들어 중복 저장하지 않음 |
| 서버 연결 실패 | 저장 실패를 설명하고 준비된 결과로 전환 | 라이브 재조회 성공으로 표현하지 않음 |
| 서버가 계속 불가 | 사전 준비한 캡처/영상이 있으면 보여 줌 | 사전 저장 화면이라는 출처 설명 |
| 종목 기록 없음 | 종목·계정·필터 확인, 준비된 다른 기록으로 이동 | 빈 화면을 성공 결과로 보고하지 않음 |
| 입력 검증 오류 | 해당 값 수정 후 저장 | 입력 유지 및 오류 위치 확인 |
| 앱 재시작 | 동일 계정 초안 복원 또는 저장 기록 재조회 | 다른 계정 초안 재사용 금지 |

캡처/영상은 구현 후 정상 동작을 실제 확인한 뒤 준비한다. 이번 작업에서 생성하거나 검증했다고 기록하지 않는다.

## 6. 시연 완료 판단과 기록

필수 완료 기준은 네 종목별 실제 저장·재조회 확인과 현장 대표 종목 한 개의 전체 흐름 성공이다. 다른 세 종목도 사전 준비 단계에서는 각각 전체 흐름을 한 번 확인한다. 신규 결과 선택 입력, 저장 실패 복구, 기존 기록 접근까지 위 체크리스트로 검증한다.

수행 후 기기·앱/백엔드 기준 revision·실행 항목·성공/실패·미실행 이유를 이 문서의 별도 검증 결과 절에 기록한다. 계획을 완료 결과로 바꾸거나 기존 QA 실패를 지우지 않는다. 후속 업무와 결정은 결정 로그에 누적한다.

이번 작업은 계획서 작성만 수행했다. 전체 테스트뿐 아니라 테스트·빌드·앱·서버·DB 실행 및 실제 시연도 수행하지 않았다.
