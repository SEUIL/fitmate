## 2. 분리와 정리

- 임시 MySQL DB에 가상 계정과 테스트 데이터를 생성했다. 기존 `fitmate` DB 회원을 제재하거나 운영자 역할을 부여하지 않았다.
- 노트북 Handoff에만 언급된 V28은 확인 가능한 Git 이력에 없어 번호를 예약했다. V29는 공지·카테고리 순서 버전 저장용 테이블 추가다.
- 기존 DB 백업은 Git에서 제외되는 `backend/data/backups/`에 보존했다. 백업은 회원 데이터가 포함될 수 있으므로 문서나 evidence에 복사하지 않는다.
- 검증 종료 시 임시 DB를 삭제하고 임시 서버와 USB 8080 전달을 종료했다. 기존 DB의 공지·제재·운영자 역할은 0건, 카테고리 version은 0임을 확인했다.
- 휴대폰의 기존 앱은 보존했다. 별도 `com.fitmate.app.dev.records` 테스트 패키지를 설치하여 실행했고, 종료 후 강제 종료했다. 이 패키지는 테스트용이며 기존 앱 교체·배포를 의미하지 않는다.
- 실계정의 운영자 메뉴 사용에는 해당 DB의 별도 역할 부여가 필요하다. 이번 검증에서 부여한 권한은 삭제한 임시 DB에만 있었다.

만료 검사는 **임시 DB의 가상 회원에 한해 제재 시각을 조정**해 단계별로 실행했다. 30일 정지의 실제 시간 경과를 기다린 것은 아니다. 짧은 정지 만료 단계에서 남은 활성 정지 1건을 확인한 뒤 기기 로그인을 검사했다.

신규 도구는 실제 HTTP로 검사했으며, Fake 4건은 별도로 표시했다. OCR 실기기 화면은 요청 0건 상태로 검증했고, 양수 집계 계산은 단위 테스트에서 확인했다.

응답 유실 검사는 기기 내부 HTTP 중계에서 원래 Idempotency-Key를 실제 서버로 전달한 뒤 응답 TCP 연결만 닫았다. 서버의 RESOLVED 상태를 확인하고 앱의 오류→최신 상태 다시 조회→상세 재진입을 통과했다. 처리 감사 기록은 재조회 전후 모두 1건이었다. 통신사 망이나 기기 전체 네트워크를 차단한 검사는 아니다.

2026-09-16 추가 실행에서는 변경한 `ServerAdminDeviceTest` 4개, 로그인 테마 1개, 확장한 진입 검사 1개를 각각 최종 통과했다. 다른 기존 실기기 검사는 앞선 실행 결과이며 17개를 한 번에 재실행한 수치는 아니다.

## 5. 발견·수정

1. 공지 작성자의 UUID를 변환기로 추가 변환하여 기존 회원 FK와 맞지 않았다. 기존 운영자 엔티티와 같은 저장 형식으로 수정 후 공지 통합 검증이 통과했다.
2. 종목 순서를 곧바로 교환하면 `fitness_sports.display_order`의 고유 인덱스와 충돌했다. 동일 트랜잭션에서 사용하지 않는 임시 순서로 옮겨 flush 후 최종 순서를 저장한다. ID·code·name·활성 상태는 보존한다.
3. 초기 신규 UI 테스트가 로딩 중 버튼을 클릭하거나 확인창 버튼에 스크롤을 요구해 실패했다. 버튼 활성화 대기와 확인창 클릭을 구분한 뒤 해당 테스트가 통과했다. 실패를 숨기거나 제품 검증 조건을 약화하지 않았다.
4. 존재하지 않는 USER 대상 신고에도 WARNING/SUSPEND가 허용됐다. 회원 존재 확인을 추가해 NONE만 허용하며, 직접 경고 요청도 403으로 거절하고 REVIEWING 상태를 보존한다.
5. 추가 페이지 테스트는 검색 전후 첫 페이지가 동일한 데이터라 검색 완료를 잘못 판단했다. 검색에서 제외되는 가상 신고를 추가해 검색 완료와 다음 페이지 조회를 구분했다. 회전 테스트는 복원된 더보기 탭을 현황 탭으로 가정한 부분을 서버 역할·도구 확인으로 수정했다.

## 6. 아직 확인하지 않은 Handoff 항목

- 실기기에서 모든 상태 필터 조합. 검색·페이지와 백엔드 RECEIVED/REVIEWING/DISMISSED 필터는 확인했다.
- 실제 게시물·댓글을 작성 후 삭제하는 전체 UI 흐름. 처음부터 존재하지 않는 게시물 근거와 반려 전용 UI는 확인했다.
- 기기 전체 네트워크 차단·지연·복구. 저장 후 응답 TCP 유실은 확인했다.
- 실기기에서 로그인 만료·운영자 권한 회수의 전체 UI 흐름. 권한 회수는 백엔드 HTTP, 만료/회수 후 화면 데이터 제거는 Android HTTP 저장소로 검증했다.
- 회전·재시작 중 미완료 공지/제재 입력의 보존과 자동 재전송 방지. 이번 진입 검사는 홈에서 센터로 다시 들어가 서버 역할을 확인하는 범위다.
- 기기 두 대의 동시 운영. 백엔드 두 운영자 동시 요청과 Fake 충돌 화면은 검증했다.

MFA·이의신청·운영 규칙·권한 관리·확장 통계는 사용자가 후속 단계로 선택했다. 이번 검사 결과가 이 기능들의 완료를 의미하지 않는다.
