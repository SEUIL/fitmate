### 실제 서버·DB에서 확인한 항목

- 본인 인바디 선택 및 측정일 보존, 타 사용자 인바디·추천·루틴 접근 거절.
- 조건 접수→완료 조회→같은 부위 대체 후보→교체→버전 충돌 거부.
- 저장→루틴 재조회 시 구성·추천 근거·조건 보존, 중복 저장은 같은 루틴 반환.
- 저장한 루틴으로 세션 생성·운동 시작, 일차별 운동 항목 연결.
- 동시 동일 요청의 AI 작업 1회 제한, 타 사용자 요청 ID로 소유자 덮어쓰기 방지.
- 취소 후 지연된 결과 무시, 120초 경과 작업의 실패 전환과 동일 요청 재시도.
- 정상 AI 제안과 잘못된 ID·예외·응답 없음에서 기본 추천 대체. **이 항목의 AI는 테스트 대역이며 외부 AI 호출이 아니다.**
- AI 호출 위치에서 실제 DB 트랜잭션이 열려 있지 않음을 확인.

### 단위·HTTP fixture 검증

- 세트·반복·휴식 상한, 날짜 누락·중복 운동·기구 위반·제외 운동·부위 편중·시간 초과 거절.

## 4. 남은 검증·적용 경계

후속 승인 후 `OpenAiWorkoutPlanLiveTest`를 추가하고 `FITMATE_LIVE_WORKOUT_PLAN_TEST=true`로 실행했다. 로컬 Spring 설정으로 해석한 OpenAI 키가 비어 있어 `AI key configuration missing; no request sent.`에서 중단됐다. 로컬 파일에는 Gemini 설정만 있으며 프로세스·사용자·시스템의 `OPENAI_API_KEY`도 미설정이다. 비밀값은 출력하지 않았다. 기기의 adb 연결은 정상으로 재확인했다. 이번 시도에서는 임시 DB·서버를 새로 시작하지 않았다.

이후 사용자가 로컬 OpenAI 설정을 추가한 뒤 같은 opt-in 검사 1개가 통과했다. 합성 인바디 수치와 운동 목록으로 실제 AI 구성을 요청하고 서버 제약 검증을 통과했으며 기본 추천 반환을 성공으로 인정하지 않는다. 키가 있는 로컬 설정 파일은 Git ignore 대상임을 확인했다.

별도 MySQL 컨테이너를 다시 생성하고 임시 서버의 datasource를 명령행에서 13384 포트의 `fitmate_plan_test`로 강제 지정했다. AI 생성 활성화는 임시 실행에만 적용했다. 실제 기기에서 합성 계정·인바디 미선택으로 동의→AI 생성→서버 검증 완료 표시→교체→저장→재조회 시 AI 출처·근거·조건 동일성→운동 시작 API를 확인했다. 이 기기 경로는 단독 실행과 후속 묶음 실행에서 각각 통과했다. 실제 인바디 수치의 외부 전송 검사는 별도의 Backend 합성 fixture로 수행했으며, 기기에서 인바디를 선택한 외부 AI E2E까지 성공한 것으로 확대하지 않는다.

첫 묶음 실행은 Compose의 `performMeasureAndLayout called during measure layout` 오류로 종료됐다. 다시 실행한 5개 묶음에서는 기본 추천 2개·실제 AI 1개·생성 취소 fixture 1개가 통과했고, 재시도 fixture 1개가 조건 화면 대기에서 시간 초과했다. 실패 fixture는 별도 프로세스 단독 실행에서 통과했다. 묶음 실행의 간헐적 불안정 원인은 미확정이며 해결 완료나 5개 전체 통과로 기록하지 않는다.

이전 opt-in 환경변수 없는 실행에서는 추천 규칙 8개·AI 응답 처리 4개가 통과하고 실제 AI 검사 1개는 건너뛰었다. 현재 Backend HTML 보고서는 후속 실제 AI 검사 1개 통과 결과다.

공개용 동의·전송·보관 정책을 확정한 상태가 아니다. 외부 구성 생성은 기본 비활성화다. 제한된 합성 조건의 실호출 성공이며 다양한 실제 조건의 품질·지연을 보장하지 않는다. 기존 운영/개발 DB에는 V23을 적용하지 않았고, 실제 사용자 데이터를 이용한 추천·건강정보 전송도 수행하지 않았다.

추천 화면에서 기존 운동 준비 흐름으로 전달되는 루틴과 서버의 실제 세션 시작을 확인했으며, 실제 운동 수행·기록 완료·운동 후 AI 리포트는 이번 검증에 포함하지 않는다.

## 5. 2026-09-15 사용자 수동 테스트용 기존 DB 연결

위 격리 검증 이후 사용자의 명시적 승인으로 기존 `fitmate-mysql`을 시작하고 백업 후 V19→V23을 적용했다. 계정 건수 유지와 V22의 기본 루틴 3개 추가, V23 성공을 확인했다. 복구 백업은 Git 제외 `backend/build/db-backups/fitmate-before-v23-20260915.sql`이며 개인정보가 포함될 수 있으므로 공유·커밋 대상이 아니다. 서버 API 200 응답과 기존 DB 연결을 확인했으며 사용자 데이터 내용은 출력하지 않았다.

## 6. 수동 테스트 발견: 분할 전체 종목이 운동 화면에 표시됨

사용자가 3일 분할의 12종목이 한 세션에 표시되는 문제를 발견했다. 서버는 완료 횟수로 현재 일차를 선택하고 해당 종목만 반환하지만, Android 시작 코드가 전체 루틴으로 만든 로컬 종목 목록을 유지한 것이 원인이었다. 서버 응답으로 로컬 운동 목록·첫 종목·목표 세트 수를 함께 초기화하도록 수정했다. 준비 화면은 전체 분할 구성임을 표시하고 완료 시 다음 일차로 순환함을 안내한다. 기존 진행 세션과 기록은 자동 수정·삭제하지 않는다.

3일×4종목 각각의 당일 목록·첫 종목·세트 수 및 빈 응답 거절 회귀 테스트 2개를 추가했다. Android 전체 단위 테스트 89개와 빌드·별도 패키지 업데이트 설치를 확인했다. 기존 실기기 통합 테스트에도 저장된 루틴의 당일 종목과 실제 앱 초기화 목록 비교를 추가했으나, 이번 수정 후 해당 서버 통합 시나리오는 아직 재실행하지 않았다. 이전 기기 검사는 API 세션 시작만 확인했으므로 앱 로컬 목록 결함까지 검증한 것으로 보지 않는다.

## 7. 승인 시안 UI 적용 후 검증

민트·딥 그린 톤, 날짜별 탭, 종목 행 안의 교체 동작, 선택 후 적용하는 교체 화면, 접이식 근거·동의 안내, 하단 주요 버튼을 적용했다. 화면의 횟수·종목·시간·측정일은 API 데이터이며 시안의 예시값을 제품 규칙으로 넣지 않았다. 저장 상태를 구분하고 운동 준비에서는 `nextSplitDayNo`를 다시 조회해 당일 종목만 보여준다. 생성 화면은 실제 서버가 제공하지 않는 세부 단계 완료율을 꾸며내지 않는다.
