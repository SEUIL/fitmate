# 검토 중 — 로그인 워드마크 통일·계정 기억 검증

- 작성일: 2026-09-11
- 최종 수정일: 2026-09-15
- 버전: v1.1
- 상태: 검토 중
- 범위: Android 로그인 화면, 암호화 세션 저장, 로그아웃 및 간편 접속

## 적용 동작

로그인 화면과 계정 조회 오류 화면의 FitMate를 홈과 동일한 공통 워드마크로 통일했다. 두 테마에서 홈의 글자 크기·굵기·자간·색상을 사용한다.

로그인의 ‘이 기기에 계정 기억’은 기본으로 켜져 있다. 이 상태로 성공한 최근 계정 1개를 기억한다. 로그아웃하면 로그인 화면에 계정과 ‘이 계정으로 계속하기’, ‘기억한 계정 삭제’가 표시된다. 로그아웃 확인창에서도 간편 접속이 유지됨을 안내한다. 기억 옵션을 끄고 로그인하면 이전 기억 정보가 제거되고 일반 서버 로그아웃을 사용한다.

간편 접속은 기존 refresh API로 인증 정보를 갱신한다. 만료·폐기 응답(400/401/403)은 기억 정보를 제거하고 이메일을 입력란에 채워 비밀번호 재로그인을 안내한다. 일시적인 서버 오류는 기억 정보를 보존한다. 오류는 해당 로그인 동작 가까이에 표시한다.

기억한 계정 삭제는 이 기기의 인증 정보만 지운다. 서버 계정이나 운동 기록은 삭제하지 않는다. 비밀번호 변경·회원 탈퇴·전체 기기 로그아웃 시에는 기억 정보도 제거한다. 기존 활성 세션의 앱 시작 시 자동 복원은 유지한다. 업데이트 전 로그인은 보존되지만 계정 기억을 활성화하려면 새 로그인 화면에서 한 번 로그인해야 한다.

## 저장 및 호환성

- 비밀번호를 저장하지 않는다. 이메일과 refresh token을 기존 Android Keystore AES/GCM 암호화 파일에 보관한다.
- `noBackupFilesDir`를 사용하며 활성 세션과 기억 계정의 인증 갱신 결과를 한 번의 AtomicFile 쓰기로 저장한다.
- 이전 버전의 암호화 세션 형식도 읽어 기존 로그인을 보존한다.
- 사용자 요청에 따라 기억 옵션을 켠 일반 로그아웃은 로컬 활성 세션만 종료하고 서버의 갱신 권한을 유지한다. 간편 접속 가능 기간은 서버 만료·폐기 정책을 따른다.
- Samsung Health 내부 UI, 백엔드 API 및 DB 스키마는 변경하지 않았다.

## 최신 main 통합 검증 — 2026-09-15

- PR #47 브랜치에 main `597c811`을 통합했다. 최신 AI 추천·리포트, 시작 화면 대기, Samsung Health 화면과 프로필 서버 통계 표시를 유지하면서 계정 기억·브랜딩 변경을 반영했다.
- Android `test assembleDebug assembleDebugAndroidTest -PfitmateIsolatedTest=true`: 단위 101개 통과, 실패·제외 0, 앱과 테스트 APK 빌드 성공.
- 실기기 첫 묶음 9개 통과: 계정 기억 6개, 실제 서버 로그인·설정·간편 접속·세션 폐기 2개, 실제 서버 추천 생성/저장 응답 유실 복구 1개.
- 실기기 두 번째 묶음 27개 중 22개 실행 통과, 조건부 5개 제외: 기존 인증·설정 15개, 추천 화면 3개, 리포트 화면 4개. 실제 AI 호출·일부 추천 서버 검사와 데모 화면 조건은 이 묶음에서 활성화하지 않았다.
- 두 묶음 합계 31개 실행 통과, 5개 조건부 제외. 실제 외부 AI 품질 비교를 이번 인증 통합 검증에서 다시 실행한 것은 아니다.
- 합성 계정의 라이트·다크·큰 글자 로그인 화면을 확인했다. 기존 로그인 형식 호환, 암호화 저장·재생성한 클라이언트 복원, 반복 접속과 만료/오류 전환을 검증했다.
- 설치 대상은 기존 데이터가 있는 `com.fitmate.app.dev.records`이며 덮어쓰기 설치했다. 사용자 계정 로그아웃·앱 데이터 초기화 없이 합성 계정과 별도 테스트 저장 위치를 사용했다.
- 업데이트 후 일반 앱 실행 명령은 성공했다. 실제 로그인 계정 화면 캡처는 개인정보 노출 가능성으로 자동 승인 검토에서 차단되어 시각 확인하지 않았다. 합성 계정 검증과 실제 사용자 화면 확인을 구분한다.
- Backend·DB 스키마·Gradle wrapper·의존성 변경은 없다. GitHub 자동 CI가 없어 직접 수행한 검증 결과를 PR에 기록한다.

## 이전 검증 결과 — 2026-09-11

Samsung SM-S947N의 격리 패키지 `com.fitmate.app.dev.records`에서 합성 계정으로 검사했다. 암호화 파일 검사도 별도 테스트 디렉터리를 사용했다.

| 검사 | 결과 | 범위 |
|---|---|---|
| Android 단위 테스트 | 66개 통과 | 기존 58개와 계정 기억 8개: 토큰 회전, 일반/전체 로그아웃, 만료/폐기, 임시 오류 재시도, 계정 교체·삭제 |
| 새 실기기 검사 | 6개 통과 | 암호화 저장·새 클라이언트 복원, 이전 형식 호환, 라이트/다크/글자 2배의 간편 접속·로그아웃 확인·삭제, 오류 복구 |
| 기존 실기기 회귀 | 22개 통과 | 인증·설정 15개, 세션 오류 3개, 로그아웃 2개, 홈 2개 |
| 실제 서버 연동 | 2개 통과 | 두 테마에서 로그인·설정 저장, 각 2회 로그아웃→간편 접속→동일 계정 조회, 서버 전체 세션 폐기 후 재접속 차단 |
| 일반 앱 빌드·설치 | 성공 | `com.fitmate.app.dev`, 기존 앱 데이터 유지 |

실기기 검사는 중복을 제외한 30개다. 오류 표시 위치 보완 후 새 검사 6개와 일반 로그인 2개 및 실제 서버 2개를 최종 코드로 다시 실행했다. 초기 테스트 실행의 화면 잠금, JUnit 반환 타입, 확인창에서 불필요한 키보드 종료 호출은 해소하고 재검증했다.

로그는 무시되는 빌드 경로 `android/app/build/remembered-regression-test.txt`, `remembered-final-device-test.txt`에 있다. 새 클라이언트를 통한 디스크 복원은 확인했으며 기기 재부팅·앱 재설치 후 유지 여부는 이번 검증에 포함하지 않는다. 큰 글자는 테스트 Compose 환경의 fontScale 2.0과 폭 320dp이며 기기 전체 설정은 변경하지 않았다.
