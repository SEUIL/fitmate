## 1. 구현 범위

`기능-개발-우선순위.md`의 P2 범위(공개·비공개 계정, 팔로우, 일반 커뮤니티, 개인 DM, 차단, 신고, 알림)를 서버 API와 MySQL Flyway 마이그레이션으로 구현했다.

### 계정 관계와 차단

- 공개 계정 팔로우는 즉시 `ACCEPTED` 처리한다.
- 비공개 계정 팔로우는 `PENDING` 요청으로 만들고, 계정 주인이 수락·거절한다.
- 거절 또는 취소한 팔로우는 다시 요청할 수 있다.
- 차단하면 양방향 팔로우/요청을 취소하며, 차단 해제만으로 관계는 복구되지 않는다.
- 차단된 두 사용자는 프로필, 피드, DM, 미디어를 서로 조회하거나 새 요청을 만들 수 없다.

### 커뮤니티와 미디어

- 게시물 생성·수정·삭제, 공개 범위(`PUBLIC`, `MUTUAL`), 피드, 좋아요, 댓글을 제공한다.
- `MUTUAL` 게시물은 상호 팔로우한 사용자만 열람한다.
- 게시물 이미지는 별도 미디어 업로드 후 최대 10개를 연결한다.
- 게시물 또는 DM에서 참조 중인 파일은 단독 삭제를 막는다.
- 현재 파일은 로컬 `data/media`에 저장한다. 운영 환경에서는 S3 등 객체 스토리지 구현으로 교체한다.

### DM, 신고, 알림

- 상호 팔로우 사용자는 즉시 활성 DM 대화를 만들 수 있다.
- 그 외 관계의 첫 메시지는 DM 요청이며, 수신자 수락 후에만 추가 메시지를 전송할 수 있다.
- 요청 거절 후에는 다시 요청할 수 있다.
- 신고는 사용자·게시물·댓글·DM 메시지 대상으로 한 사용자당 한 번만 접수한다.
- 팔로우, 좋아요, 댓글, DM 요청·메시지는 사용자의 인앱/커뮤니티/DM 알림 설정을 확인한 뒤 알림을 생성한다.
- 알림 목록, 개별 읽음, 전체 읽음, 전체 삭제 API를 제공한다.

## 2. 주요 API

| 영역 | 대표 경로 |
| --- | --- |
| 팔로우·차단 | `/api/v1/users/{userId}/follow`, `/api/v1/users/{userId}/block` |
| 커뮤니티 | `/api/v1/community/posts` |
| 미디어 | `/api/v1/media` |
| DM | `/api/v1/dm/conversations`, `/api/v1/dm/requests` |
| 알림 | `/api/v1/notifications` |
| 신고 | `/api/v1/reports` |

모든 API는 기존 JWT 인증을 사용하며, API 응답은 기존 `ApiResponse` 형식을 따른다.

## 3. 데이터베이스 변경

## 4. Android 연동 범위

- `ServerSocialApi`로 피드·게시물·좋아요·댓글·팔로우·차단·DM·알림·신고 API를 Compose 화면에 연결했다.
- 게시물 및 DM은 사진 선택 후 미디어 업로드 API를 먼저 호출하고, 응답 `mediaId`를 게시물 또는 메시지 요청에 연결한다.
- 서버가 돌려주는 미디어 경로는 인증이 필요하므로, Android HTTP 클라이언트가 access token을 포함해 바이트를 내려받아 Compose 이미지로 렌더링한다.
- 프로필 사진은 `PROFILE` 목적의 미디어 업로드 후 `PATCH /api/v1/users/me/profile`에 `profileImageMediaId`와 version을 함께 전송한다.
- 타인 프로필 사진은 프로필 열람 권한을 통과한 경우에만 `/api/v1/users/{userId}/profile-image`로 제공한다.
- 로컬 access token이 만료됐을 때도 로그아웃을 선택하면 기기 세션을 정리해 로그인 화면으로 돌아갈 수 있게 했다.

## 5. 프로필 사진 API 계약

| 동작 | 경로 | 조건 |
| --- | --- | --- |
| 이미지 업로드 | `POST /api/v1/media?purpose=PROFILE` | 소유자만, JPEG/PNG/WEBP, 최대 10MB |
| 내 프로필 사진 연결 | `PATCH /api/v1/users/me/profile` | `version`, `profileImageMediaId` 필요 |
| 타인 프로필 사진 조회 | `GET /api/v1/users/{userId}/profile-image` | 공개 계정 또는 열람 가능한 팔로우 관계 |

- 프로필에 연결된 미디어는 새 프로필 사진으로 바꾸기 전에는 삭제할 수 없다.
- 프로필 사진 URL은 `GET /api/v1/users/me`와 타인 프로필 응답에서 반환한다.

- 팔로우 서비스 단위 테스트 5개는 공개/비공개 요청, 수락, 프로필 공개 범위, 언팔로우를 검증한다.

## 7. 실기기·실제 API 검증

- Galaxy S26+에서 기존 세션 로그아웃 후 분리된 테스트 계정 로그인에 성공했다.
- 기기에서 프로필 설정 → 사진 선택 → 시스템 사진 선택기 → 선택 완료를 수행했다.
- 앱 화면 기반 임시 PNG를 사용해 실제 `업로드 → profileImageMediaId 저장 → 프로필 URL 재조회 → 인증 이미지 다운로드`를 검증했다.
- 서버 재조회 결과는 프로필 이미지 URL 존재, 이미지 HTTP 200, `image/png` 응답이었다.
- 테스트에 사용한 기기 임시 파일은 검증 후 삭제했다. 테스트 계정과 서버 미디어는 개발 DB 검증 이력으로 남아 있다.

## 8. 배포 전 수동 검증 순서

1. MySQL에 V9~V12을 포함한 Flyway 마이그레이션을 적용한다.
2. 공개 계정과 비공개 계정 두 개로 팔로우·수락·거절·차단·차단 해제를 확인한다.
3. 공개/상호공개 게시물을 생성하고, 비상호 사용자에게 `MUTUAL` 게시물이 노출되지 않는지 확인한다.
4. 게시물·DM 이미지를 첨부한 뒤 해당 미디어 삭제 요청이 거절되는지 확인한다.
5. 비상호 사용자 DM 요청, 수락, 거절 후 재요청, 차단 후 접근 거절을 확인한다.
6. 팔로우·좋아요·댓글·DM 뒤 수신자 알림 목록과 읽음 처리를 확인한다.
7. 신고를 같은 계정으로 두 번 접수했을 때 두 번째 요청이 거절되는지 확인한다.
