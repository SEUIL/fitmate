실기기 4건은 테스트 코드 인증→최종 확인→역할 저장, 제한 인증→신청 접수→신청 내역, 결정 저장 후 응답 유실→입력 잠금→동일 키 확인, 샘플 검사와 실제 저장 분리를 검증했다. 최초 실행은 화면 잠금 때문에 진행되지 않았고 잠금 해제 후 재실행했다. 규칙 테스트의 키보드 창 포커스 실패 1건은 단독 재실행에서 통과했다.

별도 실서버 4건은 수동 테스트 DB에 합성 회원을 생성해 수행했다. 사용자 화면에서 접수한 신청의 공개 처리 결과를 확인하고 내부 메모 비노출 및 기존 일반 로그인 유지도 검사했다. 시험에서 부여한 운영자 역할은 회수하고 활성화한 규칙은 비활성화했다. 합성 신고·신청·처리 이력은 확인용으로 남아 있다.

## 발견하고 보완한 문제

- 규칙 검사에서 계정 행을 잠그면 동시에 작성한 메이트 글의 외래 키 잠금과 충돌했다. V33 전용 작성자 잠금으로 분리하고 작성 시작 전에 잠가 동시 요청을 직렬화했다. 기존 동일 멱등키 메이트 동시 생성 검사를 다시 실행했다.
- 마지막 잠금 검토에서 공유 잠금의 배타 잠금 전환도 피하도록 중복 키 update로 직접 직렬화했다. 변경 후 규칙·메이트 HTTP 통합 검사를 다시 통과했다.
- 전체 시험의 여러 Spring 서버가 기본 연결 풀을 유지해 MySQL 연결 상한에 도달했다. 테스트 실행 환경에서 최대 풀 4·최소 유휴 0으로 제한했다. 수동 테스트 서버 설정은 바꾸지 않았다.
- 기존 OCR 검사는 DB가 비어 있다고 가정했다. 집계 값에 따른 실패율과 별도의 빈 기간을 모두 검사하도록 보완했다.
- 기존 카테고리 정렬 검사가 다음 테스트에 변경된 순서를 남겼다. 원래 순서를 finally에서 복구하도록 수정했다. 새 일회용 DB에서 전체 시험이 통과했다.
- 이의신청 목록의 비동기 상태를 화면 루트에서 관찰하도록 보완했다. 실기기 UI 시험에서 응답 후 로딩 표시가 남던 경우를 수정하고, 임시 진단 로그를 제거한 상태에서 승인·결과 왕복을 재검증했다.

## DB·기기 분리와 남은 확인

- V30~V33은 자동 테스트 전용 DB에서 먼저 검증했다. 기존 적용 migration은 수정하지 않았으며 V28은 계속 미사용 번호다.
- 사용자가 “백업 후 테스트 환경에 반영”을 승인했다. 수동 DB `fitmate_admin_tools_test_1789486405609`를 백업하고 V30~V33 적용 및 Flyway 32개 검증을 완료했다. 원래 `fitmate` DB는 V29를 유지한다.
- 백업은 Git에서 제외된 `backend/data/backups/fitmate_admin_tools_test_1789486405609-before-v30-20260916-012517.sql`에 보관했다(1,123,725 bytes). SHA-256: `08BB3C515D60E6ED1860E95DE0743334B6F18EC1C301FCB9384846EDB1660BA7`.
- 백엔드 재시작과 `com.fitmate.app.dev.records` 앱 업데이트를 완료하고 테스트 운영자의 더보기 화면을 열어두었다. 고정 코드는 local 프로필의 `FITMATE_ADMIN_DEMO_AUTH_ENABLED`·`FITMATE_ADMIN_DEMO_CODE`로만 설정했다.
- HTTP fixture UI 검사는 별도 `com.fitmate.app.dev.opscorecheck`, 실서버 UI 검사는 수동 테스트 앱에서 수행했다. 결과 화면 4개를 확인했다.
- 실제 TOTP/MFA, 운영 배포, 결과 Push, 장기 보관·자동 정리 정책, 규칙 탐지 후보의 자동 제재는 구현하지 않았다.
- 정지 만료는 테스트 데이터의 시각 조정으로 검사했으며 실제 기간 경과를 기다린 결과가 아니다. 이번 실서버 이의신청 UI 검증은 경고 해제이며, 중첩 정지 해제는 백엔드 통합 검사 결과다.

## 승인된 운영자 UI 개편 검증

- 4개 탭(현황·신고·이의신청·운영 도구), 회원·콘텐츠의 관련 기록 이동, 한글 권한명, 민트 아이콘, 공통 행·버튼·상태 필터·제목 스타일을 반영했다. 원문과 신고자 설명을 별도 구획으로 표시한다.
- 운영 도구 이동 시 부모 화면의 조회 상태가 사라지지 않게 유지하고, 관련 기록 화면의 복원과 뒤로가기를 검사했다. 대기 수치는 접수·검토 중 전체 건수임을 명시하며 다른 현황 지표와 구분한다.
- Android 단위 검사 117건 통과, 실패·제외 0. Debug 앱 및 기기 테스트 APK 빌드 통과.
- 실기기 고유 19건 통과: `AdminCenterDeviceTest` 5건, `AdminCoreDeviceTest` 4건, `ServerAdminDeviceTest` 4건, `AdminCoreLiveDeviceTest` 6건. 앞 절의 이전 실행 건수와 중복 합산하지 않는다.
- 실서버에서 반려·경고·응답 유실 복구·20건 초과 검색 조회·운영자 권한·규칙 검토·이의신청 접수와 결과를 재검증했다. 신규 2건은 라이트·다크에서 4개 탭과 모든 운영 도구의 진입·복귀를 확인한다.
- 최초 연속 실행 중 규칙·신청자 검사에서 키보드 창 포커스 실패가 발생했다. 단독 재실행으로 통과했고, 기기 절전으로 Compose 화면을 찾지 못한 시도도 기기를 깨운 뒤 다시 통과했다. 메뉴 왕복 검사는 조회 완료 전 비활성 뒤로가기를 누르던 동기화를 보완했다.
- 화면 이미지에서 라이트·다크의 대비·민트 아이콘·목록 배치를 확인했다. 현재 기기 기본 글자 크기 기준이며 모든 접근성 글자 배율을 검사한 것은 아니다.
- 테스트 앱 `com.fitmate.app.dev.records`에 적용했다. 백엔드·DB는 기존 수동 테스트 환경을 유지하며 UI 개편으로 추가 migration을 적용하지 않았다.
- 후속 ‘최근 처리’ 수정: 단순 문자열을 민트 아이콘·처리 종류·요약·시각이 구분된 목록으로 바꿨다. 기존 응답의 action·occurredAt을 보존하고 알려진 처리 코드를 한글로 표시한다. 저장소 매핑 검사 6건·Debug 빌드 통과, 테스트 앱 설치 후 실제 최근 처리 3개 항목의 표시를 확인했다. 이 변경 후 전체 117건을 재실행한 것은 아니다.
- Git 반영 직전에는 최근 처리 변경까지 포함해 Android 전체 단위 117건을 다시 실행해 실패·제외 0을 확인했다. Debug 빌드도 통과했다. GitHub 자동 CI는 등록되어 있지 않아 직접 수행한 검증 결과를 PR에 기록한다.
