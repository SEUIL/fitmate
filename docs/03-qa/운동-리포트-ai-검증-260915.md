# 운동 리포트 AI 검증 — 검토 중

- 작성일: 2026-09-15
- 최종 수정일: 2026-09-15
- 버전: v0.7
- 상태: 검토 중

## 검증 대상

2번 기능의 근거 기반 종합 서술·비동기 생성·저장·Android 연결. 아래 최신 검사와 이전 후보 선택 방식의 검증을 구분한다.

## 최종 입력 화면·기기 회귀 검사

- `/options`에서도 본인 완료 헬스 세션을 확인하고 `samsungHealthAvailable`을 반환한다. 격리 DB에서 타 사용자 접근 거부, 요약 저장 전 false/후 true를 검증했다.
- 연결 요약이 없으면 Samsung 선택을 비활성화하고 연결 위치를 안내한다. 인바디 선택 제목에 측정일을 표시하며 화면 상태 복원 후에도 날짜를 유지한다. 새 기기 검사에서 확인했다.
- 백엔드 전체 검사와 실제 AI 포함 기기 묶음 결과는 [추천 최종 회귀 검사](./운동-추천-확장-검증-260914.md)를 따른다. 기기 묶음에는 별도 합성 계정의 실제 AI 종합 리포트 저장·재조회·화면 재진입이 포함된다.
- 실제 Samsung Health 초기 설정 후 개발용 Data SDK 읽기 모드와 FitMate 운동 읽기 권한을 확인했다. SDK 사용 가능 및 최근 7일 운동 조회 성공, 결과 0건을 확인했다. 실제 기기 원본→세션 연결→AI 리포트는 동기화된 운동 기록이 없어 미검증이다. 합성 요약의 서버·AI 검사를 실제 기기 원본 검사로 취급하지 않는다. [삼성 개발 모드 공식 안내](https://developer.samsung.com/health/data/guide/developer-mode.html)를 참고했다.
- 실제 건강 수치·계정·기기 식별자와 화면을 증거 파일에 저장하지 않았다. 기존 로그인과 데이터는 보존했다.
- 앱 프로세스를 강제 종료하고 다시 실행한 후 기존 로그인, 서버 운동 목록, 기존 저장 AI 리포트 v1 재조회·표시를 직접 확인했다. v2 생성·화면 재진입은 위 합성 실기기 왕복 검사를 따른다. 데이터 초기화나 새 실제 사용자 분석 요청은 하지 않았다.

### 최종 서술 품질 보완

설명을 짧게 쓰고 핵심 해석을 먼저 배치하며 같은 주의·행동을 반복하지 않도록 생성 지침을 보완했다. 해요체와 한국어 목표명을 명시하고, 요약은 목표·세션·핵심 운동에 집중하며 선택 인바디·Samsung 맥락은 관찰 항목에 배치한다. 근거 인용 수 제한과 의미 검토는 유지했다.

실제 합성 비교 과정에서 빈 검토 응답 1건, 후속 문구 조정 후 필수 출처 누락 및 MISSING_CITATION 거절 각 1건이 발생했다. 검토 응답 상한을 500→1,500 토큰으로 늘리고 요약에 모든 출처를 몰아 넣지 않도록 구성 지침을 보완했다. 빈 응답의 공급자 내부 원인은 확정하지 않았다. 실패는 기본 대체 대상으로 유지하고 성공으로 세지 않았다.

최종 근육 증가/목표만 다이어트/RPE만 변경의 3개 응답은 모두 AI 생성·서버 검증·AI 검토를 통과했다. 다이어트 목표 표기, RPE 차이에 따른 등 운동 중심 해석, 중복을 줄인 단일 다음 행동을 실제 문장으로 확인했다. 공급자 응답 테스트 5개도 통과했고 잘린 검토 응답은 계속 거부한다. 최종 `backend/build/ai-report-quality.json`, 초기 실패 `ai-report-quality-readability-initial.json` 및 `ai-report-quality-citation-initial.json`은 합성 데이터만 담은 Git 제외 증거다. 이 소수 사례가 모든 응답의 정확성·품질을 보장하지는 않는다.

## 추천 연결 및 실제 AI 통제 비교

추천 분할 개선 후 실제 앱의 추천→교체→저장→당일 운동 세트 입력·완료→AI 종합 리포트→저장 재조회→다음 일차 순환 검사를 완료했다. 상세는 [추천 검증 기록](./운동-추천-확장-검증-260914.md)의 1→2번 연결 검사를 참고한다. 별도 합성 비공개 계정을 사용했으며 기존 로그인과 실제 운동 데이터는 유지했다.

전체 입력 합성 스냅샷을 고정하고 `WorkoutAiQualityLiveTest`에서 실제 AI 비교를 수행했다. 기준(근육 증가·동일 RPE), 목표만 DIET, RPE만 랫 풀다운 9/다른 종목 5로 바꾼 3개 최종 응답 모두 생성·서버 구조 검증·AI 근거 검토를 통과했다. 사람이 실제 설명을 읽어 다음 차이를 확인했다.

| 변경 | 실제 결과의 차이 |
|---|---|
| 기준 근육 증가 | 종목별 수행량·반복·RPE를 같은 조건으로 비교하도록 제안 |
| 목표만 다이어트 | 운동 기록을 감량 성공으로 단정하지 않고 반복 가능한 활동과 식사 기록을 함께 추적하도록 제안 |
| RPE만 변경 | 등 종목의 높은 주관적 노력과 수행량 변화를 연결하여 다음 등 운동에서 수행 조건을 비교하도록 제안 |

초기 목표 변경 응답은 근거 검토에서 거절됐다. 목표별로 활동 기록과 감량/근성장 성과를 구분하도록 생성 지침을 보완한 뒤 3개를 재검사해 통과했다. 검토 기준을 완화하거나 기본 대체를 성공으로 집계하지 않았다. 공급자 응답 단위 5개도 재통과했다. 초기 합성 결과는 `backend/build/ai-report-quality-initial.json`, 최종 비교는 `ai-report-quality.json`에 Git 제외로 보존한다. 이는 각 조건의 소수 실호출 비교이며 동일 조건 반복 안정성이나 운동 전문성 검수 완료를 뜻하지 않는다.

공개 서비스 정책·보관·삭제·사용자별 호출 제한·비용/지연/대체 비율 집계는 사용자의 지시에 따라 이번 작업에서 제외했다.

## 종합 서술 v2 변경 검증

기존 후보 선택 결과에 대한 사용자 피드백 후 `grounded-narrative-v2`를 구현했다. 목표·종목별 변화·RPE·선택 체성분·기기 기록을 연결한 자유 서술을 생성하고 별도 AI 호출로 근거 일치 여부를 검토한다. 구조·근거·숫자 본문·중복·선택 정보 포함은 서버가 검사한다. AI 검토는 의미적 오류를 완전히 보장하지 않는다. 화면은 종합 설명을 우선 표시하고 근거를 접어 둔다.

- Android 단위 93개 및 앱·기기 테스트 APK 빌드 통과.
- 서버 최종 24개 통과: 규칙 5, 서술 근거·역호환·한국어 치환 6, 공급자 응답 5, 격리 MySQL 통합 6, 실제 합성 AI 2. 모의 검토 거절·비정상 응답·구버전 동의·근거 없는 수치·잘못된 참조도 검사했다.
- 합성 실제 AI 검사: 운동 습관/입문/이전 비교 없음과 근육 증가/이전 종목 비교/RPE/인바디/기기 요약 시나리오의 생성·검토 통과. 각각 다른 목표와 기록에 따른 설명을 확인했다. 목표만 바꾼 통제 실험이나 대규모 품질 평가는 아니다.
- 기존 DB에는 별도 합성 계정만 추가하여 전체 입력으로 실제 AI 생성→READY/AI→저장→동일 응답 재조회에 성공했다. 이전 실제 사용자 데이터는 변경하지 않았다.
- 실제 종합 결과는 종목별 증가·감소·유지와 동일하게 기록된 RPE를 설명했고, 누락된 휴식 기록을 다음 행동으로 제안했다. 인바디는 단일 측정이므로 추세를 단정하지 않았고 시간 출처를 합산하지 않았다.
- 초기 전체 데이터 요청은 검토 거절로 기본 대체되었고 별도 실행에서 생성 요청 시간 초과도 확인했다. 각 문장에 실제 사용한 모든 출처를 인용하도록 보완하고 리포트 전용 호출 제한 시간을 30초로 분리한 후 합성 실제 AI·서버 왕복이 통과했다. 실패 기록도 성공으로 집계하지 않는다.
- 새 화면 설치를 처음 시도할 때 ADB가 연결 기기를 찾지 못했으나, 최종 확인 시 재연결되어 앱 업데이트를 완료했다. 실제 서버에서 생성한 합성 응답 재생 화면 검사 1개, 기본 해석·취소·이전 결과 다크 모드 호환 검사 3개가 통과했다. v2 캡처는 `android/app/build/insight-narrative-v2-top.png`, `insight-narrative-v2-details.png`이며 실제 사용자 로그인은 유지했다.
- v2 실기기 실제 왕복 검사 `liveAiGenerationPersistsAndCanBeReopened` 1개도 통과했다(15.106초). 별도 합성 계정으로 새 동의→실제 AI 생성·검토→DB 저장·재조회→화면 재진입을 확인했다. 최종 생성 단계 문구와 중복 구분선을 정리하고 앱 빌드·설치·합성 결과 표시를 다시 확인했다.
- Git 제외 합성 결과: `backend/build/insight-full-demo.json`(실제 서버·DB 왕복), `insight-narrative-live.json`과 `insight-narrative-habit-live.json`(실제 AI 독립 검사). 기존 JSON에는 v2 실행 결과가 저장되므로 아래 v1 숫자 비교 설명은 과거 검증 기록이다.

## 전체 입력 더미 시나리오 — 이전 후보 선택 v1 검증

사용자가 더미 데이터 추가를 요청하여 기존 DB에 별도 비공개 합성 계정을 생성했다. 기존 사용자 기록은 변경하지 않았다. 프로필은 근육 증가·6개월~1년, 이전/현재 운동은 각각 2026-09-07/09-14, 선택 인바디는 09-12의 체지방률 22%·골격근량 34kg이다. Samsung Health 요약은 실제 기기 측정이 아닌 API로 넣은 합성 값(활동 39분·평균 심박 126bpm·285kcal)이다. FitMate 세션 45분과 합산하지 않았다.

각 운동 3세트·10회로 벤치 프레스 40→45kg, 랫 풀다운 40→35kg, 레그 프레스 80→80kg을 기록했다. 실제 외부 AI 호출 결과 READY/AI를 확인했고 저장 후 재조회가 동일했다. 선택된 해석은 볼륨 1,200→1,350kg 증가, 1,200→1,050kg 감소, 2,400→2,400kg 동일이었다. 다음 행동은 수행 조건 비교와 체감 강도 기록이었다.

저장된 실제 응답을 기기 내 응답 재생으로 앱의 기존 리포트 화면에 표시하는 선택 실행 검사 `showFullSyntheticLiveResult` 1개가 통과했다. 이 화면 검사는 추가 외부 AI 호출이 아니다. 기존 앱 로그인은 유지했다. Git 제외 증거는 `backend/build/insight-full-demo.json`, `android/app/build/insight-full-demo-top.png`, `insight-full-demo-details.png`다. 모두 합성 데이터다.

한계: 전체 입력이 있어도 AI는 서버 후보 중 최대 3개 관찰을 선택한다. 이번 응답은 운동 비교 3개를 선택하여 인바디·Samsung 수치는 참고 정보에만 나타났다. 여러 종류의 정보를 연결해 자유롭게 종합 설명하는 구현은 아니다.

통합 검사: V24 적용, 생성→저장→재조회, 프로필 변경 후 스냅샷 유지, 본인 인바디 및 연결 기기 요약의 명시적 선택, 시간 중복 합산 없음, 타 사용자 세션·리포트·인바디 접근 거부, 추천 동의 재사용 거부, 요청 ID 충돌, 동일 세션 중복 생성, 트랜잭션 밖 AI 실행, 잘못된 AI·예외 시 기본 대체, 취소 후 늦은 결과 무시, 만료 요청 재분석.

환경은 기존에 승인한 `fitmate-plan-manual-test` 컨테이너의 별도 `fitmate_insight_test` 스키마(13384)다. 합성 계정만 생성했다. 사용자 DB `fitmate-mysql`(3307)은 이번 단계에서 변경하지 않았다.

실기기는 연결된 Android 16 기기에서 사용자가 잠금 해제한 뒤 실행했다. 기본 동의 해제→기본 해석, 생성 취소→재입력, 저장된 AI 표시의 다크 모드·글씨 2배를 검사했다. 첫 기본 화면 검사는 기기의 다크 모드를 따랐으므로, 밝은 모드를 명시하도록 보완 후 최종 3개를 다시 통과했다.

Git 제외 증거: `android/app/build/insight-device-final.txt`, `insight-result-light.png`, `insight-result-dark-large.png`; 서버 JUnit XML은 `backend/build/test-results/test/`에 있다. 시안은 합성 예시이며 실제 분석 증거로 사용하지 않는다.

## 기존 DB 적용 및 실제 실기기 왕복

- 사용자가 기존 DB 백업·V24 적용 및 요청별 별도 동의에 따른 리포트 AI 활성화를 승인했다.
- `fitmate-mysql`의 V23을 확인한 뒤 일관된 전체 백업을 `backend/build/db-backups/fitmate-before-v24-20260915.sql`에 보존했다. 민감한 복구 파일이므로 Git에서 제외하고 내용을 출력하지 않았다.
- 로컬 서버를 재시작하여 V24 migration 성공, 서버 HTTP 응답, 기존 계정·운동 세션·루틴 수 유지(합성 검증 데이터 추가 전)를 확인했다. 새 리포트 테이블 외의 기존 데이터 수정은 없다.
- 서버는 18084에서 추천 AI와 리포트 AI를 각각 활성화한 상태다. 앱의 8080 USB 연결을 유지했다. 기본 설정의 리포트 AI 비활성 값은 그대로이며 이번 로컬 실행에만 활성화 인수를 적용했다.
- `liveAiGenerationPersistsAndCanBeReopened` 실기기 검사 1개 통과. 별도 합성 계정으로 운동 완료→앱 내 리포트 동의→실제 AI→DB 저장→재조회→화면 재진입을 검증했다. 결과 `source=AI`와 완료 세트 수·저장 응답 동일성을 확인했다. 기존 사용자 로그인이나 건강 기록은 읽거나 전송하지 않았다.
- 첫 실행은 기기 화면이 꺼져 Compose 화면을 찾지 못했다. 잠금이 해제된 상태임을 확인한 후 화면을 깨우고 테스트 중 화면 유지 처리를 추가하여 통과했다. 초기 실패와 최종 결과는 각각 `android/app/build/insight-device-live-ai.txt`, `insight-device-live-ai-final.txt`에 보존했다. 합성 화면은 `insight-live-ai-result.png`다.
- 합성 테스트 계정과 운동 기록은 별도로 추가되었으며 임의 삭제하지 않았다. 사용자 앱을 다시 열고 서버 실행을 유지했다.

## 실측 검증 한계 및 제외 범위

- 실제 Samsung Health는 권한·연결·최근 운동 없음까지 확인했다. 동기화된 실제 운동의 연결·분석은 미검증이다. 공개 서비스용 동의·보관·삭제 정책, 호출 제한, 비용·지연·대체 비율 집계는 사용자 지시에 따라 작업 범위에서 제외했다.
- 자동 실제 기기 왕복 검사는 인바디·Samsung 미선택 조건이다. Samsung 요약의 서버 DB 검증과 합성 외부 AI 전송 검증은 앞선 독립 검사 결과를 따른다.

## 사용자 요청에 따른 직접 화면 조작 검증 — 당시 v1 기록

- 사용자가 직접 화면을 조작하여 올바른 테스트를 수행해 달라고 요청했다. 현재 로그인과 기존 완료 기록을 유지한 상태에서 화면의 버튼·선택·뒤로가기·스크롤로 검증했다.
- 동의 해제·선택 정보 미사용 상태에서 기본 해석 생성과 기본 출처 표시를 확인했다.
- 본인 인바디 목록을 불러와 기록을 선택하고, 승인된 전송 범위의 별도 동의를 체크한 뒤 실제 AI 해석을 생성했다. Samsung Health는 미선택했다.
- 결과 출처 AI, 화면 이탈 후 같은 기록 재진입, 선택 인바디 측정일·사용 정보 유지, Samsung 미사용 안내를 확인했다. 운동 원본·인바디 원본은 수정하지 않았고 리포트 요청만 추가했다.
- 실제 기록의 날짜·수치·식별자와 화면은 로컬 로그·문서·fixture 파일로 저장하지 않았다. 이 기록은 기능 동작 여부만 기술한다.
- 당시 사용성 발견: 연결한 Samsung 요약이 없어도 선택 가능하고 선택 인바디의 접힌 제목에 측정일이 없었다. 후보 선택 방식은 AI와 기본 결과의 내용 차이가 작았다. 이후 종합 서술 v2와 위 최종 입력 화면 보완으로 변경했다.
