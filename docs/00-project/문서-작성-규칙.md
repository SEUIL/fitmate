# 문서 작성 규칙

이 문서는 발표 준비 기간에 사용하는 FitMate `docs/` 구조와 문서 작성 규칙의 canonical 기준이다.

## 폴더 사용

| Folder | Purpose |
|---|---|
| `00-project/` | 프로젝트 현황, 결정·회의 로그, 기획 원본 |
| `01-spec/` | MVP 범위, 사용자 흐름, 화면, 데이터 모델 |
| `02-technical/` | Android 구조, Samsung Health 연동, 권한, 데이터 흐름 |
| `03-qa/` | 검증 결과, 시연 순서, 장애 대응 |
| `assets/` | 공용 이미지, 다이어그램, PDF, PPTX 등 첨부 자료 |

`00-project/1차기획/`은 기존 기획 산출물 원본 보관 폴더다. 명시 요청 없이 수정하지 않는다.

## 문서 작성 원칙

- 발표 준비에 필요한 문서만 만든다.
- 하나의 문서는 하나의 주제를 다룬다.
- 문서는 `.md`를 기본으로 하고, 파일명은 kebab-case 또는 의미가 명확한 한국어를 사용한다.
- 새 문서에는 작성일, 최종 수정일, 버전, 상태(`작성 중`, `검토 중`, `확정`)를 기록한다.
- `확정` 문서 변경 시에는 최종 수정일과 버전을 함께 갱신한다.
- 회의 결정과 Action Item은 `00-project/결정-회의-로그.md`에 누적한다.
- 이미지, PDF, PPTX 등의 공용 첨부 자료는 `assets/`에 둔다.

## AI 작업 규칙

- 대상 문서를 먼저 읽고, 원본 보존이 필요한 자료는 이동보다 복사를 우선한다.
- `00-project/1차기획/`의 원본 자료는 명시 요청 없이 수정하지 않는다.
- 상태가 `확정`인 문서는 사용자 확인 후 수정한다.
- secret, token, password, 개인정보를 문서에 기록하지 않는다.
