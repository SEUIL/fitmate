# 검토 중 — FitMate UI 개편 계획

- 작성일: 2026-09-10
- 최종 수정일: 2026-09-11
- 버전: v0.22
- 상태: 검토 중
- 목적: 현재 개발·실기기 상태를 바탕으로 전체 UI 개편 범위와 화면별 이미지 시안의 검토 순서를 정한다.
- 기준 코드: `main`, `592a4cc`

## 1. 진행 방식

2026-09-11 후속 점검에서 홈 FitMate 옆 심볼을 제거하고 가로 화면·키보드 사용 시 운동 입력란이 가려지는 문제를 보완했다. [후속 점검 기록](../03-qa/ui-후속점검-260911.md)에 실기기 검사 30개·단위 테스트 58개 통과, 구현 캡처 8장과 남은 야외 GPS·외부 AI·TalkBack 검증을 정리했다.

사용자가 요청한 순서는 **계획 → 화면별 이미지 시안 → 피드백·수정 → 구현 → USB 실기기 검증**이다. 현재 시작 화면 A안, 공통 UI 기반·홈·루틴 선택·운동 진행, 2차 개인 운동 7개 화면, 3차 메이트, 4차 커뮤니티·DM, 5차 프로필·인바디, 6차 인증·일반 설정, 7차 대표 상태 8개를 Android에 적용했으며, 이 문서가 전체 화면 구성의 최종 확정이나 구현 완료를 뜻하지 않는다.

- **기존 기능·데이터·API·권한 정책을 유지하고 UI/UX만 개편한다.** 표현·배치·탐색·입력 편의가 변경 대상이다.
- 플랜핏 Android 앱의 운동 중심 정보 구성과 시각적 명료함을 참고한다.
- 라이트·다크를 동등하게 지원하고, 현재 시스템 테마 선택도 유지한다.
- 첫 시안은 홈·루틴 선택·운동 진행 3개 화면으로 공통 스타일을 검토한다.
- 공통 스타일에 대한 피드백을 반영한 뒤 나머지 화면의 시안을 순차 제작한다.
- 화면별 시안을 검토한 후 해당 묶음의 Android 구현을 시작한다.

### 팀원 작업 영역 제외

**프로필 → 설정 → Samsung Health 화면과 그 내부 UI는 이번 시안·UI 구현 대상에서 제외한다.** 다른 팀원이 진행하는 영역이다. 프로필과 일반 설정의 나머지 화면은 개편 범위에 유지하고, Samsung Health로 연결하는 기존 진입 경로·동작은 보존한다. 공통 테마·컴포넌트 변경이 제외 화면에 간접 적용되지 않도록 구현 시 영향 범위를 먼저 확인한다. 연동 로직·권한·SDK·연결 상태는 변경하지 않는다.

## 2. 현재 개발 상태

### 확인 기준과 한계

2026-09-10 USB debugging으로 연결된 Samsung SM-S947N에서 `com.fitmate.app.dev`를 직접 실행했다. 설치 앱은 versionName `1.0`, versionCode `1`이며 최종 업데이트 시각은 기기 표시 기준 같은 날 17:21이다. 로컬 debug APK의 수정 시각은 17:20이다. 화면과 코드 경로는 일치하지만 APK와 커밋의 바이너리 동일성은 검증하지 않았다.

최초 조사에서는 플랜핏이 설치되지 않아 공식 공개 앱 이미지를 참고했다. 이후 사용자가 설치·로그인한 **플랜핏 Android 앱 `com.mih.planfit`, v3.236.4(4001098)**를 같은 USB 기기에서 직접 조작했다. 아래 플랜핏 관찰은 2026-09-10 해당 설치 버전 기준이며 웹사이트 레이아웃을 참고한 것이 아니다.

기존 문서의 미완료 목록 일부는 현재 코드보다 오래됐다. 특히 초기 화면 연동 명세와 기능 개발 우선순위 문서의 과거 진행 요약만으로 구현 여부를 판단하지 않는다.

### 플랜핏 직접 사용 범위

로그인 다음 초기 설정부터 운동 종료·기록 재조회까지 진행했다. 실제 운동 수행이 아닌 UI 확인이며, 초기 설정에는 기본값·테스트 선택값을 사용했다.

| 확인 영역 | 직접 조작·관찰한 내용 | FitMate 적용 판단 |
|---|---|---|
| 초기 설정 | 단계 진행선, 선택 타일, 숫자 입력, 건너뛰기, 맞춤 플랜 요약 | 선택 상태와 입력 위계 참고. 설문 단계나 수집 항목 추가는 제외 |
| 운동 홈 | 플랜 요약, 운동 미리보기, 직접 만들기, 저장한 운동 진입 | 기존 운동 시작·이어하기를 주 행동으로 강화 |
| 추천 운동 미리보기 | 운동별 행, 세트·중량·횟수, 순서 변경 진입, 운동별 더보기 | 루틴의 긴 연결 문장을 읽기 쉬운 행으로 전환 |
| 운동 안내 | 기구 이미지, 운동 가이드/메모·분석/기록 탭 | 정보 위계만 참고. 플랜핏 이미지·동영상 자산 사용은 제외 |
| 운동 진행 | 워밍업 생략, 현재 운동·경과 시간, 중량 입력, 세트 완료, 전체 목록 복귀 | 현재 세트 입력과 완료 동작 중심으로 재배치 |
| 세트 후 상태 | 중량 체감 선택, 휴식 타이머 시트, 시간 조절·중단 | 기존 FitMate RPE와 휴식 상태를 명확히 표현. AI 강도 조절 추가는 제외 |
| 종료·결과 | 운동 평가, 공개 범위 선택, 결과 카드, 완료 요약 | 기존 완료 리포트의 요약→상세 순서에 적용 |
| 분석 | 최근 7일 그래프, 무게/칼로리/시간 전환 | 지표 표기 원칙만 참고. 새 기간 집계·칼로리 추정 기능은 제외 |
| 프로필 기록 | 월 캘린더, 날짜별 요약, 운동 상세 재조회 | 기존 기록 목록·필터·상세를 우선 정돈. 캘린더는 첫 시안 범위 밖 |
| 커뮤니티 | 인기 피드의 사진 그리드, 팔로잉/인기/클럽 탭 | 탭·정보 계층 참고. FitMate의 본문 중심 피드와 기능 유지 |
| 설정 | 계정·앱·커뮤니티 항목, 현재 값과 이동 표시, 토글 | 설정을 의미별 행으로 묶고 현재 상태를 표시 |
| 직접 운동 구성 | 빈 목록, 운동 추가 시트, 검색·부위·기구 필터·선택 개수 | 기존 루틴 편집의 추가·순서·제거·상세·대체 동작을 읽기 쉽게 배치 |

무료 이용 범위에서 확인했다. 구독 안내는 닫았으며 유료 기능 내부·추천 알고리즘 품질은 검증하지 않았다. 확인한 앱 화면은 다크 테마였고 설정에서 라이트 전환 항목을 찾지 못했다. 따라서 **FitMate 라이트 시안은 같은 정보 위계로 별도 설계**하며 플랜핏 라이트 화면을 확인했다고 표현하지 않는다.

체험 결과 플랜핏 계정에 테스트 초기 설정과 **1세트 운동 기록 1건이 비공개로 저장**됐다. 공유·공개 게시·댓글·반응·메시지·구독 결제는 실행하지 않았고 건강 데이터 연동도 건너뛰었다. 탐색 종료 시 플랜핏 운동 홈으로 돌아왔다. 이 테스트 값은 실제 사용자 신체정보나 운동 성과로 해석하지 않는다.

## 3. 현재 UI의 우선 개선점

| 우선도 | 관찰 | 개편 방향 |
|---|---|---|
| 높음 | 홈에서 큰 바로가기와 커뮤니티 피드가 우선하고 운동 시작은 작은 보조 버튼이다 | 오늘 할 운동/이어하기를 가장 먼저 인지하게 배치 |
| 높음 | 홈의 ‘운동 일지’가 커뮤니티로 연결된다 | 개인 운동 기록과 커뮤니티 작성의 이름·목적지를 구분 |
| 높음 | 홈 운동 수는 로컬 배열, 프로필 통계는 서버 완료 기록을 기준으로 한다 | 이번에는 출처·의미를 구분해 표기. 집계 기준·조회 로직 통일은 별도 기능 수정으로 분리 |
| 높음 | 루틴은 운동 이름을 화살표로 이어 붙여 보여 준다 | 운동별 행, 운동 수, 실제 제공되는 세트 정보와 명확한 선택 CTA |
| 중간 | 운동 준비는 선택한 루틴 설명을 반복하고 연동 안내가 크게 차지한다 | 운동 목록을 확인하면서 준비할 수 있게 구성, 연동은 선택 설정으로 정돈 |
| 중간 | 주요 버튼이 연한 민트 사각형·진한 초록 알약 등으로 혼재한다 | 주 행동/보조 행동/위험 행동의 스타일과 크기 통일 |
| 중간 | 큰 테두리 카드와 중복 제목으로 정보 밀도가 낮은 화면이 있다 | 행과 구분선 중심 목록, 카드가 필요한 정보만 묶기 |
| 중간 | 운동 기록이 프로필 내부 탭에 있어 접근과 탐색에 여유가 적다 | 홈에서 기록으로 직접 진입, 기록 화면의 독립 헤더와 목록 구조 검토 |
| 중간 | 러닝·DM에 개발 도구가 일반 화면 흐름에 노출된다 | 시연에 필요한 접근성을 유지하면서 개발 전용 영역의 시각적 우선순위 낮추기 |

현재 실행되는 홈은 `SocialDesign.kt`의 `SocialHome`이다. `FitMatePrototypeApp.kt`에 남은 이전 `HomeScreen`과 고정 주간 통계는 현재 홈 경로가 아니므로 개편 대상으로 혼동하지 않는다.

## 4. 디자인 방향 제안

### 플랜핏에서 참고할 부분

위 직접 사용 결과를 우선 근거로 삼는다. [플랜핏 공식 소개](https://planfit.ai/ko)의 공개 앱 이미지는 보조 자료다.

- 중립적인 배경과 명확한 밝기 차이로 정보 우선순위를 만든다.
- 민트 계열 포인트를 주 행동, 선택 상태, 진행 상태에 집중한다.
- 운동 목록은 반복 가능한 행 구조로 빠르게 읽게 한다.
- 운동 진행은 현재 운동, 중량·횟수, 완료한 세트와 다음 행동이 중심이다.
- 핵심 버튼은 손이 닿기 쉬운 하단 영역을 검토한다.

FitMate의 지역 메이트·모집 조건·문의·커뮤니티는 기존 제품 기능으로 유지한다. 플랜핏의 AI 코칭·운동 영상·근육 그림 등을 이미 구현된 기능처럼 추가하지 않는다. 시안에 새로운 이미지가 필요하면 별도 제작 자산임을 구분하고 구현 시 자산 수급 범위를 확인한다.

플랜핏에서 관찰한 긴 온보딩, 반복 구독 안내, 종료 후 공유·반응 유도 단계는 개편 목표에 포함하지 않는다. 운동 일러스트가 없는 FitMate 화면은 현재 운동명·입력·기록에 공간을 배분한다. 시안 이미지에만 존재하는 장식이 실제 필수 기능처럼 보이지 않게 한다.

### 내비게이션 초안

첫 시안은 현재 **홈 / 메이트 / 커뮤니티 / DM / 프로필** 5개 탭을 유지하고 홈의 운동 진입을 강화한다. 기존 사용 흐름을 비교하기 쉽고 메이트 기능의 비중도 보존할 수 있다.

운동 기록의 하단 탭 승격이나 DM 위치 이동은 첫 시안에 포함하지 않는다. 홈에서 기존 프로필의 운동 기록으로 연결하는 바로가기는 UX 개선안으로 제시한다. 현재 커뮤니티로 연결되는 ‘운동 일지’는 목적지가 드러나는 이름으로 바꾸고 커뮤니티 접근을 보존한다.

## 5. 화면별 시안 제작 순서

앱 실행 직후의 공통 시작 화면 00은 [시작 화면 A/B 시안 및 A안 구현 기록](./검토중-ui-시안-시작화면.md)에서 관리한다. 로고 중심 A안을 적용했고 B안은 비교 자료로 보관한다. 기존 기능 화면 01~31의 번호와 기능 범위는 유지한다. 계정 확인 뒤 기존 로그인/앱 진입/오류 경로로 이동하고 강제 대기나 새 시작 버튼은 추가하지 않는다.

각 번호는 주요 화면 1개를 뜻한다. 화면 내부 탭·입력 단계·상태는 해당 화면의 추가 컷으로 관리한다. 모든 화면을 한 번에 생성하기보다 앞선 묶음에서 정한 공통 디자인을 재사용한다.

기존 번호 32 Samsung Health 연결은 팀원 담당으로 제외하며 이번 시안 대상은 주요 화면 31개다. 운동 준비·리포트에 존재하는 연동 관련 동작은 유지하고, Samsung Health 내부 화면으로 범위를 확대하지 않는다.

### 첫 3개 화면의 구체 구성

각 화면의 구조·문구는 시안 검토용 제안이며 기능 동작을 변경하는 명세가 아니다. 루틴 선택과 운동 준비는 기존 별도 단계로 유지한다.

| 화면 | 위에서 아래로의 배치 | 주 행동·보조 동작 | 필수 추가 상태 |
|---|---|---|---|
| 01 홈 | 제목·알림 → 운동 시작/이어하기 영역 → 기존 운동 수 요약 → 메이트·기록·인바디 바로가기 → 커뮤니티 미리보기 → 기존 5탭 | 주 행동은 기존 운동 선택 또는 이어하기. 메이트·커뮤니티·DM·인바디·알림 경로 보존 | 진행 중 운동 있음/없음, 게시물 빈 상태, 소셜 조회 실패 |
| 02 루틴 선택 | 화면 제목 → 추천/기본/내 루틴 탭 → 루틴명·운동 수 → 운동별 이름·기존 목표 값 → 해당 루틴 선택 → 만들기·기기 저장 루틴 진입 | ‘이 루틴으로 운동’은 기존 준비 화면으로 이동. 복사/수정/삭제는 루틴별 더보기로 표시 가능 | 추천 조건 미충족, 내 루틴 없음, 로딩, 오류·재시도, 저장 중, 삭제 확인 |
| 03 운동 진행 | 경과 시간·진행 상태 → 현재 운동·이전 기록·전체 운동 보기 → 현재 세트 중량/횟수/RPE·단위 → 메모 → 기록한 세트 → 휴식 상태 | 하단 주 행동 ‘이 세트 기록’/‘세트 수정’. 휴식 조작은 보조 영역/시트. 운동 종료·안전 안내 접근 유지 | 입력 오류, 기록 성공, 기존 세트 편집, 휴식 중/일시정지, 재진입, 종료 저장 중·실패 |

운동 진행의 주 행동은 **세트 기록**이다. 운동 종료를 같은 강조 버튼으로 나란히 두지 않는다. 다만 세트 기록 이후 휴식 자동 시작 여부, 운동 전환, 단위 환산, 세트 계산은 기존 로직을 그대로 따른다. 플랜핏의 휴식 프리셋·증감 단위를 그대로 복제하지 않고 FitMate의 기존 30/60/90초 설정·30초 추가·일시정지/재개를 유지한다.

첫 이미지 검토에서는 3개 정상 화면 × 2테마 = **개별 PNG 6장**과 검토 문서의 화면별 라이트/다크 비교표 3개를 제공했다. [1차 시안](./검토중-ui-시안-1차.md)에 개별 원본과 비교표를 연결했다. 이어 [추가 상태 시안 v1](./검토중-ui-시안-추가상태.md)으로 홈 이어하기·내 루틴 빈 상태·루틴 편집·세트 수정·휴식 중·종료 저장 실패 **6개 상태 × 2테마 = PNG 12장**을 제작했다. 아직 별도 이미지가 없는 로딩·입력 오류·저장 중·삭제 확인 등은 구현 전 상태 점검 목록에 유지한다. 휴식 시트는 구현 전에 키보드와 뒤로가기, 시트 닫기 후 타이머 지속 상태까지 점검한다.

### 후속 화면의 배치 기준

주요 상태와 공통 기준은 [7차 시안: 상태·공통 규칙](./검토중-ui-시안-7차-상태-공통규칙.md)에 정리했다. 계정 조회 실패·알림/인바디 빈 목록·판독 대기·검수 누락·저장 응답 불명확·기록 삭제 확인·로그아웃 확인의 8개 상태를 두 테마, PNG 16장으로 제작했다. 여백·글자·버튼·선택·오류·진행·확인 창의 통일 기준과 제안 색상 대비, 화면별 남은 검증을 함께 관리한다.

인증·설정 묶음은 [6차 시안: 인증·설정](./검토중-ui-시안-6차-인증-설정.md)에 정리했다. 로그인·가입 4단계·건강정보 동의·알림·팔로우 요청·설정 위/아래·화면 모드·계정 관리의 12개 컷을 두 테마, PNG 24장으로 제작했다. 서버 알림 설정과 실행 중 Push 선호 UI, 서버 약관 동의와 로컬 건강/위치 동의를 구분하고 기존 요청·검증·이동 경로를 유지한다. Samsung Health는 진입 항목만 보존한다.

프로필·인바디 묶음은 [5차 시안: 프로필·인바디](./검토중-ui-시안-5차-프로필-인바디.md)에 정리했다. 프로필·편집 위/아래·인바디 목록 위/아래·상세 위/아래·직접 입력·사진 확인·판독 검수의 10개 컷을 두 테마, PNG 20장으로 제작했다. 기존 프로필 사진 즉시 저장, 건강정보 동의, 사진 전송 안내, 판독값 확인과 중복 저장 방지를 보존한다. 편집·목록·상세를 나눈 컷은 같은 스크롤 화면이며 새 경로가 아니다.

커뮤니티·DM 묶음은 [4차 시안: 커뮤니티·DM](./검토중-ui-시안-4차-커뮤니티-dm.md)에 정리했다. 피드·댓글 시트·작성·수정·DM 목록·대화·받은 요청의 7개 컷을 두 테마, PNG 14장으로 제작했다. 기존 공개 범위·초안·사진 제한·요청 수락 전 송신 제한을 유지한다. 운동 기록 첨부와 일부 DM 메뉴의 서버/로컬 처리 차이는 검토 문서에 명시하고, 미제작 오류·메뉴·차단 상태는 후속 검토에 유지한다.

메이트 묶음은 [3차 시안: 메이트](./검토중-ui-시안-3차-메이트.md)에 정리했다. 목록·필터·미신청 상세·작성 폼 위/아래·모집자 신청 관리·문의 목록·문의 대화의 8개 컷을 두 테마, PNG 16장으로 제작했다. 서버 allowedActions·신청 상태·모집 상태·문의 writable과 집결 위치 공개 조건을 보존한다. 수정 제한·읽기 전용·오류 등 미제작 파생 상태는 후속 검토에 유지한다.

개인 운동 묶음은 [2차 시안: 개인 운동](./검토중-ui-시안-2차-개인운동.md)에 정리했다. 04 운동 선택·05 운동 준비·06 러닝 설정·07 러닝 진행·08a 헬스 완료 리포트·08b 러닝 종료/저장·09 운동 이력의 7개 컷을 두 테마, PNG 14장으로 제작했다. 헬스 서버 완료 리포트와 러닝 저장 전 입력을 구분하고 실제 기존 경로를 따른다. 위치 권한·GPS 오류·저장 중 등 미제작 상태는 검토 문서의 후속 목록에 유지한다.

| 인증·설정 | 기존 가입 순서를 유지하고 입력·오류를 가까이 배치. 일반 설정은 제목·현재 값·이동/토글로 통일. Samsung Health 내부 UI 제외 | 필수/선택 동의, 계정 기능, 알림, 라이트·다크·시스템, Samsung Health 진입 경로 |

## 6. 이미지 산출물과 검토 방식

- 화면별 라이트 PNG와 다크 PNG를 제공한다. 작게 축소된 전체 보드만으로 검토하지 않는다.
- 동일 화면의 두 테마를 나란히 배치한 비교표와 변경점 설명을 함께 제공한다.
- 세로형 Android 화면 비율을 사용하고 이미지 안의 한국어 제목·버튼을 읽을 수 있는 해상도로 만든다.
- 파일명은 `01-home-light-v1.png`, `01-home-dark-v1.png`처럼 화면·테마·버전을 구분한다.
- 검토용 이미지는 `docs/assets/ui-redesign/` 아래에 보관한다. 현재 1차 기본 화면 6장·추가 상태 12장·2차 개인 운동 14장·3차 메이트 16장·4차 커뮤니티/DM 14장·5차 프로필/인바디 20장·6차 인증/설정 24장·7차 상태 16장·시작 화면 A/B 4장, 현재 검토본 PNG 126장을 각 검토 문서에서 연결한다. 부위별 지방량 v2 반영 전 원본 2장도 보관하여 저장소 PNG는 총 128장이다.
- 예시 이름·운동·숫자는 합성 데이터로 구성하고 실제 계정·건강정보를 재사용하지 않는다.
- 생성 이미지의 숫자·한글·아이콘은 검토한다. 구현 명세와 충돌하면 정확한 문구·동작은 명세를 기준으로 수정한다.
- 일반 화면 검토 후 빈 상태·로딩·오류·비활성·진행 중 상태를 추가 컷으로 확인한다.

각 묶음은 정보 순서, 주 행동의 위치, 글자·간격, 라이트/다크 가독성, 기능 누락 여부를 검토한 뒤 수정한다. 먼저 정한 공통 스타일이 바뀌면 후속 화면에도 같은 기준을 적용한다.

## 7. 구현 경계와 검증 기준

### 시안 검토 후 구현 순서

공통 색상·Typography·간격·버튼 → 승인된 주요 화면 → 파생 화면·상태 → 실기기 회귀 순서로 적용한다. 현재 API 계약과 기능을 바탕으로 화면을 개선한다. 새 API·집계 변경·추천 알고리즘·저장 정책 변경은 이번 UI 구현 범위에 포함하지 않으며, 필요성이 발견되면 별도 검토 항목으로 남긴다.

### 기능 보존 대조표

| 기존 기능 | UI에서 바꿀 수 있는 부분 | 보존 검증 |
|---|---|---|

| 헬스 세션 | 현재 세트 강조, 입력·휴식·전체 목록 배치 | kg/lb, 중량·횟수·RPE·메모, 세트 수정/삭제, 타이머, 상태 보관·복구, 종료 저장·재시도 |

구현 검토는 같은 입력으로 개편 전후 이동 목적지·저장 데이터·오류 조건을 대조한다. 기존 기능을 숨겨 접근할 수 없게 하거나, API에 없는 ‘AI 추천’·칼로리·주간 성과를 시안에 추가하지 않는다.

주요 파일 경계:

- `android/app/src/main/java/com/fitmate/app/ui/theme/`: 두 테마·글자·공통 토큰
- `SocialDesign.kt`, `FrontendComponents.kt`: 홈·프로필·소셜·공통 요소
- `FitMatePrototypeApp.kt`: 실제 화면 라우팅·운동 선택·준비·진행
- `ServerRoutines.kt`, `RunningFlow.kt`, `ServerRecords.kt`: 서버 운동 경로
- `ServerMateFlow.kt`, `MateDesign.kt`: 실제 메이트 경로
- `InbodyFlow.kt`, `InbodyDetailsDesign.kt`: 인바디 경로
